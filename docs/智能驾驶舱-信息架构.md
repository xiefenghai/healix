## 1. 产品目标

### 1.1 一句话

让健管师打开机构工作台后，进入 **健管智能体**：Agent 先给今日建议，对话中可点动作落到闭环；左侧喂人、右侧看结果与待审草稿——**人确认后才生效**。

### 1.2 解决什么问题

| 现状 | 痛点 |
|------|------|
| 依从看板、工作台任务、患者详情、Care Copilot、OCR、报告分散多入口 | 每天多菜单跳转，上下文丢失 |
| AI 已点状落地，但入口弱 | 对外/对内都不够「AI 产品」 |
| 纯运营工作台首页 | 能干活，但主卖点（AI）不在 C 位 |
| 纯全屏聊天 | AI 感强，但红人/催办/人审草稿缺少稳定工作面 |

### 1.3 成功标准（信息架构层）

1. 默认落在驾驶舱；**第一眼是对话**，且 Agent 已给出今日简报  
2. 点左侧优先人后，对话自动带上该患者上下文；右侧同步快照与待确认草稿  
3. 常用动作可在 **气泡内卡片** 一键触发（提醒 / 开随访 / 生成方案草稿等），仍走人审路径  
4. 原「依从性看板」「工作台」保留为专业视图；驾驶舱是智能体编排层  

### 1.4 阶段关系（叙事）

```text
现在：业务闭环底座 + OCR / 方案生成（点状 AI）
   ↓
补洞（燃料）：W4 用药按次、依从日快照/机构趋势、检查单 OCR 等
   ↓
下一程：智能驾驶舱 = 健管智能体对话（主）+ 运营上下文（辅）
```

## 2. 一屏布局（v0.2 · 对话为主）

### 2.1 桌面宽屏

```text
┌─────────────────────────────────────────────────────────────┐
│ 顶栏：机构切换 | 摘要芯片（待办/红人/超期） | 搜索患者 | 消息   │
├──────────────┬──────────────────────────────┬───────────────┤
│              │                              │               │
│  A. 今日优先  │     B. 健管智能体（主）        │  C. 上下文    │
│  （左·喂人）  │     大对话区                  │  （右·结果）  │
│              │     Agent 先开口 + 动作卡      │  快照/草稿箱  │
│              │                              │               │
├──────────────┴──────────────────────────────┴───────────────┤
│ D. 底栏快捷（弱化）：新建随访 | 上传检验 OCR | 生成方案 | 报告 │
└─────────────────────────────────────────────────────────────┘
```

相对 v0.1 的变化：原「中间焦点患者大卡片」改为 **对话主区**；原「右栏 AI 副驾」改为 **患者快照 + 待确认草稿**；AI 能力上移到中栏对话。

### 2.2 窄屏

- A 可折叠为抽屉  
- B 对话占满主区  
- C 在选中患者后以底部 Sheet 展开  
- D 收成「+」

## 3. 模块说明

### 3.1 顶栏

| 元素 | 说明 |
|------|------|
| 品牌/标题 | Healix · **健管智能体**（副标题可写智能驾驶舱） |
| 机构切换 | 沿用现有选机构语义 |
| 摘要芯片 | 待办 / 红人 / 超期只读汇总（点击可筛 A 或唤起对话追问） |
| 搜索患者 | 选中后注入 B 上下文，并刷新 C |
| 消息角标 | 复用消息中心；无则可二期 |

### 3.2 A. 今日优先（左 · 给 Agent 喂人）

**Tab**：须立即处理 / 今日关注 / 我的在办  

| 卡片类型 | 数据来源 | 展示要点 |
|----------|----------|----------|
| 依从红人 | 依从性看板 | streak、方案/用药类型 |
| 超期 / 高优任务 | 工作台任务 | `PLAN_NUDGE` / `FOLLOW_UP` / `PLAN_CREATE` / `REPORT_REVIEW` / `METRIC_ALERT` 等 |
| 待审 AI 产物 | 方案 draft、报告 AI 摘要 | 「待你确认」 |
| 患者申请回访 | `FOLLOW_UP` + `source=PATIENT_REQUEST` | 高优 |

**交互**：点击卡片 → B 注入该患者（系统消息或上下文条）→ C 刷新为该患者；可选自动向 Agent 发隐式「处理此人」。

### 3.3 B. 健管智能体（中 · 主入口）

| 元素 | 说明 |
|------|------|
| 开场 | Agent **先开口**：今日简报（建议优先处理的人 + 理由） |
| 气泡动作卡 | 如「处理张敏」「查看全部红人」「提醒患者」「开用药随访」「生成方案草稿」 |
| 输入框 | 「问我任何关于患者或今日工作的问题…」；支持附件（检验单 → OCR 预填链路） |
| 能力边界 | 与 Care Copilot **同源**；不读患者私聊；不直接 publish / 不直接写库 |

对话中的动作一律落到现有 API；成功后在对话里回执，并在 C「草稿箱」出现待确认项（若适用）。

### 3.4 C. 上下文面板（右 · 结果与人审）

| 块 | 说明 |
|----|------|
| 当前患者条 | 姓名、病种、依从率、关键指标、C 是否激活 |
| 待确认草稿 | 方案草稿、OCR 预填、报告点评草稿 |
| 快捷链 | 查看完整档案、管理报告等钻取原页 |
| 人审动作 | 「应用到方案（进草稿）」「写入点评」等——**禁止一键发布绕过人审** |

无选中患者时：C 可展示机构级「今日简报摘要」或占位引导点左栏。

### 3.5 D. 底栏快捷（弱化）

熟练用户冷启动：新建随访、上传检验 OCR、生成/调整方案、管理报告。视觉权重低于对话，避免抢 AI 主入口。

## 4. 与现有页面的关系

| 现有能力 | 驾驶舱关系 |
|----------|------------|
| 依从性看板 | A 数据源；专业视图保留 |
| 工作台任务 | A + 对话动作闭环；详情可侧滑 |
| 患者详情多 Tab | C 为摘要；完整档案钻取 |
| Care Copilot | **升级为 B 主对话**（带机构/患者上下文） |
| 检验 OCR / 方案生成 / 报告 AI | 对话触发 → C 草稿箱人审 |
| 消息中心 | 触达执行（如 `STAFF_NUDGE`），非聊天室 |
