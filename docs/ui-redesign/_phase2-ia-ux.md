## 0. 设计基线回顾（不重复 Phase 1）

下列 Phase 1 已锁定的结论，本文**严格遵守**，不再讨论：

- 方向：「诊室级秩序感 × 有人在旁的陪伴感」
- 5 条原则（§1）：一屏一焦点 / 色为信息 / 临床级可读 / 圆角与阴影成阶梯 / 呼吸优先于描边
- L1 焦点卡规格：56px 圆头像 / `r-xl 28` 圆角 / `teal-700 #0b7a66` 实底（零渐变） / `elev-3` teal 染色阴影 / 全页唯一深色块
- L2 一级内容卡：`r-lg 20` + `#fff` + `elev-2`；L3 内嵌 tile：`r-md 14` + `n-50` 或 hairline
- 字号字重纪律：正文 ≥13px、对比度 ≥4.5:1、900 只给 ≥18px 数字、11px 是语义下限
- 反 slop 10 条禁令（emoji 当图标 / 左侧 4px accent 竖条 / 双层 radial 光斑 / 大面积渐变铺底 / 999 胶囊泛滥 / 10px 语义文案 / 全 900 字重 / 纯灰填满界面 / 装饰光与玻璃拟态 / 全站同一阴影）
- 令牌块见 Phase 1 §6，Phase 3 直接引用

## 2. L1 健管师焦点卡：承载内容与状态机

### 2.1 容器硬约束（来自 Phase 1，零自由度）

| 项 | 值 |
|---|---|
| 容器底色 | `teal-700 #0b7a66` **实底**，零渐变；左上 12% 白色单点柔光（可选 `radial-gradient(0 0, rgba(255,255,255,.12), transparent 50%)`） |
| 圆角 | `r-xl 28px` |
| 阴影 | `elev-3` = `0 16px 32px rgba(14,159,131,.14), 0 2px 8px rgba(19,34,46,.06)` |
| 内边距 | `20px` 上下 / `20px` 左右 |
| 头像 | 56×56 圆 / `teal-800` 首字底 / 2px `teal-100` 环 |
| 全页 | **唯一**深色块；后续模块间距 `24px`（焦点后留白） |

### 2.2 卡的骨架（始终保留的字段）

```
┌────────────────────────────────────────────────────────┐
│  [●●● 在线 / 离线 / 未读关怀 / 未分配 / 加载]   ← 12px 状态点│
│                                                         │
│  ┌──┐   张健管师 · 您的专属健管师                       │
│  │56│   "今天血压记了吗？记得饭后 1 小时再测"   ← 13·500 │
│  └──┘                                                   │
│       营养师 · 5 年陪伴您          [去沟通]              │
└────────────────────────────────────────────────────────┘
```

| 区域 | 字号/字重 | 颜色 | 备注 |
|---|---|---|---|
| 状态点 | 12px（mini 阶）·700 | `teal-300`（在线）/ `n-400`（离线）/ `danger`（未读关怀 · 但**禁用左 4px accent 条**） | 用图标 `van-icon` + 文字双通道，不靠纯色 |
| 姓名 | 17px·800 | `#fff` | 最多 6 字，超出截断为「张健管…」（`text-overflow:ellipsis`） |
| 陪伴语 | 13px·500 | `rgba(255,255,255,.86)` | **1 行为限**；服务端预生成模板 |
| 角色 · 陪伴时长 | 11px·700 | `teal-300` | 例：营养师 · 陪伴您 5 年 |
| 主按钮 | 30×auto 高 / `r-pill 999` / `teal-600` 实底 | 白字 13·700 | 文案根据状态切换（见 §2.3） |

### 2.3 状态机（5 态，每态的字段与动作）

#### 态 A：健管师「在线」且无未读（默认态）
- 状态点：`van-icon success` + 12px 文字「在线」（绿，`teal-300`）
- 陪伴语模板（服务端按时段返回）：
  - 早（5–11 点）：「早安，今天血压记得测一下」
  - 中（11–14 点）：「中午好，饭后散步 10 分钟更稳」
  - 下午（14–18 点）：「下午好，记得按时吃药」
  - 晚（18–22 点）：「晚上好，今天数据都齐了」
- 主按钮：`去沟通` → `/care-chat?contact=1`（沿用现有）
- 次按钮（如有）：`打电话` → tel:`<phone>`；**仅当有电话号时显示**

#### 态 B：健管师「离线」
- 状态点：`van-icon clock-o` + 12px「离线 · 预计 X 分钟回复」
- 陪伴语：「我不在，先留个言，我看到会回你」
- 主按钮：`留言` → `/care-chat?contact=1&mode=leave-msg`
- 次按钮：`查看关怀记录` → `/care-chat?contact=1&tab=history`
- 不允许出现"催促/警告"语义（用户为慢病中老年，压力感反人性）

#### 态 C：健管师有「主动关怀未读」
- 状态点：`van-icon comment-o` + 12px「X 条新消息」（红，`danger`，`#fff` 文字）
- 陪伴语：「张健管师给你发了 X 条提醒」
- 主按钮：`查看消息` → `/care-chat?contact=1&unread=1`
- **触发**：进入页面后 5 秒内未点击 → 卡片轻微抖动一次（`@keyframes nudge`，320ms×2，respect `prefers-reduced-motion`）

#### 态 D：「未分配健管师」（无专属 / 系统未派单）
- 卡片**降级为浅底**：`teal-50` + `1px teal-200` 边 + `elev-2`（不染 teal）
- 状态点：`van-icon info-o` + 12px「为你匹配中」（`info` 色）
- 陪伴语：「正在为你匹配合适的健管师，约 24 小时内确认」
- 主按钮：`查看进度` → `/care-chat?contact=1&state=matching`
- **不出现深色背景**（避免承诺感与现实不符）

#### 态 E：「加载中」
- 卡片**保留深色骨架**（避免布局抖动），但内容区显示 3 个 `n-200` 圆角灰块（`shimmer` 动画）
- 头像：默认 `teal-700` 实底 + 内置「...」三点 loading
- 持续 ≤ 800ms 即直接跳 A；超过 1.5s 跳 E-ext（见下）
- **E-ext 加载失败**：替换为错误态（不显示深色底）

> **E-ext 加载失败态**（补充）：
> - 退化为 `n-50` 浅卡 + `1px n-200` 边 + 文字「健管师信息加载失败」+ 按钮「重试」

### 2.4 无就诊人时 L1 的兜底

当 `hasPatient === false`（`.join-card` 触发条件）：
- **直接用 `.join-card` 替换 L1 焦点卡**（不是追加）
- 兜底卡规格：`r-xl 28` + `n-50` 底 + `1px n-200` 边 + `elev-2`
- 内容：「请先添加就诊人或使用激活码」+ 按钮「去添加」→ `/patient-cards`
- 首屏其余模块（Hero / 屏 1 的待办 / 速记）按正常顺序堆叠

### 2.5 卡的点击目标

| 区域 | 点击行为 | 路由 |
|---|---|---|
| 卡片主体（除按钮外） | 进入与该健管师的聊天 | `/care-chat?contact=1` |
| 「去沟通 / 留言 / 查看消息」按钮 | 同上 + 自动定位到对应消息 | `/care-chat?contact=1[&unread=1][&mode=leave-msg]` |
| 「打电话」次按钮 | 触发系统拨号 | `tel:<phone>` |

### 2.6 卡内字段后端约定（建议新增或确认）

| 字段 | 类型 | 示例 | 用途 |
|---|---|---|---|

## 3. 依从性驱动机制：把"展示型"改造成"驱动型"

### 3.1 现状问题（确认痛点）

| 现象 | 现状代码 | 用户痛点 |
|---|---|---|
| 火苗条只是"回顾" | `.reward-strip` 静态显示天数 / 豆 / Lv | 用户漏打卡后没有任何"怎么补"的引导 |
| 漏打卡没有补救路径 | `rewardMakeupHint` 文案存在但**没有强按钮入口** | 用户看到文字也不知道下一步 |
| 任务卡只有「完成 / 跳过」二元动作 | `.act-btn.primary` + `.act-btn.ghost` | 漏掉一项后用户无「我现在补做」路径 |
| 连续天数断档处理缺失 | `freezeCards > 0` 时文案温柔但没按钮 | 用户不知道保护卡是否自动扣、扣几张、什么时候扣 |
| 正向激励只展示不驱动 | 🔥 + 18px 天数 + 「+N 豆」 | 用户没感觉"打卡的价值"，下一次容易漏 |

### 3.2 改造总原则（符合 Phase 1 禁令）

> **任何提示都不能用「左侧 4px 彩色 accent 竖条」**——这是 Phase 1 §5 硬禁令 #2。
> 替代方案：**整卡浅色底色 + 32px 图标容器 + 文字层级**（参考 Phase 1 §3.1「类别用整卡浅色底」）。

### 3.3 漏打卡的提示形态（3 级，可共存）

#### 级 L1：屏内轻提示（`hx-flag` 形式，**沿用 style.css**）
- 位置：今日待办卡内，火苗条下方
- 容器：`teal-50 #effaf6` 浅底 + `r-sm 12` + `i` 标签 `teal-600` 实底 + 文字 `teal-700 #0b7a66`
- 标签文字：「未打卡」
- 主文字：「昨天有 X 项任务未完成，**补打卡可续火苗**」
- 触发：用户进入首页时若 `rewardMakeupHint !== ''` → 立即出现

#### 级 L2：模块级强提示（**新增**，**不用 accent 条**，用整卡浅色 + 大图标）
- 触发条件：连续 2 天未打卡 / `freezeCards === 0` 且今日过半未打卡
- 位置：替换屏 1 第 7 项「L3 健康速记入口」→ 整卡变为「漏打卡补救」卡
- 容器：`r-md 14` + `warn-bg #fff3da` + `r-sm 12` 内嵌图标容器（`van-icon warning-o` 32×32 橙底）+ 文案 + 主按钮
- 字段：
  - 标题：「昨天 X 项任务未完成 · 火苗倒计时 1 天」
  - 副文：「补打卡 1 项即可续上，否则明天火苗熄灭」
  - 主按钮：`去补打卡` → `/care-plan?day=yesterday`
  - 次按钮：`使用保护卡`（仅 `freezeCards > 0` 时显示）→ 直接调用 `useFreezeCard()` API

#### 级 L3：系统级强提示（**延后到 1.5 期**）
- 不在本期落地，但接口预留：`POST /api/c/v1/me/rewards/freeze-card?action=use`
- 推送渠道：今日 18:00 仍 `todayActive === false` 且 `freezeCards > 0` → 站内信 + 通知中心

### 3.4 补卡 / 补救路径（具体路由）

| 场景 | 触发 | 路径 |
|---|---|---|
| 昨天有方案任务未完成 | 点击 L1 提示 / L2 卡片「去补打卡」 | `/care-plan?day=yesterday` |
| 昨天缺一次测量 | 同上 | `/care-plan?day=yesterday&type=METRIC` |
| 漏服药 | 点击火苗旁 `·漏服` 角标 | `/medications?day=yesterday` |
| 漏打卡连续 3 天以上 | 系统级兜底 | `/achievements?tab=streak-recovery` |
| 火苗快熄灭 | 系统兜底 + 通知 | `/achievements?alert=streak` |

### 3.5 连续天数断档的处理（决策表）

| 情况 | UI 表现 | 行为 |
|---|---|---|
| 昨日未打卡 + `freezeCards > 0` | 火苗条文案：「今天 +N 豆 · 保护卡 X 张备用」 | 0 动作（保持现状） |
| 昨日未打卡 + `freezeCards === 0` + 今日 23:00 前 | L1 提示：「昨天未打卡 · 补打卡可续」+ 「去补」按钮 | 点击进入补打卡 |
| 昨日未打卡 + `freezeCards === 0` + 今日 23:59 后 | 火苗条图标变灰（`rs-flame.dim`）+ 文字「已熄灭 · 点击重新开始」 | 点击进入 `/achievements?tab=streak-restart` |
| 今日已打卡但即将断档 | 无额外 UI（保持简洁） | 0 |

### 3.6 正向激励的呈现位置（克制原则）

> Phase 1 P1「一屏一焦点」要求不在首屏堆多个激励气泡。本期正向激励**只**放在以下 3 处：

1. **屏 1 火苗条**（`reword-strip`，沿用）：**仅数字 + 文案 + Lv 徽章**；禁止再加气泡/勋章/动画
2. **任务打卡完成瞬间**：勾选 `hx-ck` 由灰变 teal 时，**仅 200ms scale 0.9 → 1**（沿用现有 transition），**不弹 toast、不加光效**——已有 toast「打卡成功」保留

#### 入口 A：屏 1 「L3 健康速记入口横滑」——**新增**

#### 入口 D：「健管师」——**移到 L1 焦点卡**

- 从 4 列常用服务里**完全移除**（详见 §2）
