# Healix C 端 · 界面设计方案 v11

> **主题：舵式导航 × 诊室秩序**
> 适用范围：`frontend-user`（C 端 H5）全站导航骨架 + 首页 / 健康 / 发现 / 我的 四屏
> 技术栈：Vue 3 + Vant 4 · 设计基准 390×844 · PingFang SC
> 配套产物：`c-shell-v11.html`（可交互原型）、`v11-home / health / discover / me / sheet.png`
> 前置文档：`Healix首页视觉规范-v8.md`（本方案在其令牌体系上做增量，不推翻）

---

## 0. 一句话说清这次改什么

> **把「每个健康动作都要先找入口」改成「拨一下拇指就能记」。**

v8 解决的是**首页好不好看、层级清不清楚**。v11 解决的是**整个 App 动不动得起来**。

现状的硬伤不在视觉，在结构：记录类页面（饮食 / 运动 / 饮水 / 睡眠 / 心情 / 用药 / 体重）全部是 `meta: { hideTab: true }` 的堆叠页，用户每记一次数据，都得「进首页 → 找速记入口 → 进二级页 → 填写 → 保存」。慢病管理的核心行为是**高频、低价值感、易放弃**，路径每多一步，日活的折损都是复利的。

参考对象是薄荷健康——它把这件事解决得最彻底。

## 1. 参考系：向薄荷学什么，不学什么

薄荷健康的产品骨架有一处非常聪明：**底部舵式导航，中间凸起的「＋」直接弹出「记饮食 / 记运动 / 记体重 / 发动态」**。核心动作永远离拇指 1 次点击，这是它日活能撑起来的结构性原因。

但它也被公开的竞品分析点出过问题：**首页内容塞到 8 屏、整体两种浅色系导致「找不到重点」**。

所以 v11 的取法是**拆开取**——学它的结构，不学它的密度。

| 薄荷的做法 | 好在哪 | v11 如何处理 |
|---|---|---|
| 舵式导航 + 中间 FAB | 核心动作 1 次点击直达 | ✅ **全盘采纳**，改成「记一笔」八入口 |
| 弃轮播 + 金刚区，全卡片化 | 注意力集中，不被打断 | ✅ 采纳，首屏零轮播 |
| 瓷片区（tile 网格）承载记录模块 | 模块可视、扫一眼就懂 | ✅ 用于「指标总览」与「快记面板」 |
| 低饱和绿 + 大面积白 | 清爽、不刺激、适合天天看 | ✅ 延续，品牌绿不换 |
| 「我的」页宽松排版、行更高更宽 | 好点、好读，中老年友好 | ✅ 采纳，列表行高 52px |
| 首页堆 8 屏内容 | ❌ 找不到重点 | ⛔ **不采纳**，用 v8「一屏一焦点」+ 724px 预算硬约束 |
| 金刚区 3 种以上彩色图标 | ❌ 视觉凌乱 | ⛔ **不采纳**，限定 1 主色 + 8 组品类语义色 |
| 发现页图 / 文 / 大字号混排 | ❌ 几秒内不知道看哪 | ⛔ **不采纳**，单列卡片流，一屏 2.5 张卡 |

一句话：**要薄荷的拇指效率，不要薄荷的信息焦虑。**

## 2. 核心改造：平铺四 Tab → 舵式五 Tab

### 2.1 结构变化

| | 现状（`App.vue`） | v11 |
|---|---|---|
| Tab 数 | 4（首页 / 健康 / 发现 / 我的） | 5 位（首页 / 健康 / **＋** / 发现 / 我的） |
| 记录入口 | 分散在首页速记区、「我的」列表、各二级页 | 统一收进中间 FAB |
| 记录页形态 | 8 个 `hideTab` 堆叠页 | 不变（仍可独立访问），但**新增 1 级直达** |
| 导航组件 | `<van-tabbar>` 默认样式 | 自定义 `.dock`（需替换，见 §8） |

> **为什么不是加第 5 个 Tab 而是 FAB**：Tab 是「去哪」，FAB 是「做什么」。把「记一笔」做成 Tab 会和「健康」争夺语义，且 Tab 位置有限。FAB 凸起于 dock 之上，是**动作**而非**目的地**，语义更准。

### 2.2 入口深度实测对比

| 用户动作 | 现状路径 | 步数 | v11 路径 | 步数 |
|---|---|---|---|---|
| 记一次血压 | 首页找速记 → 血压页 → 填写 → 保存 | 4 | FAB → 血压 → 填写 | 3 |
| 记一顿饭 | 首页 → 速记 → 饮食页 → 加餐 → 搜索 → 保存 | 6 | FAB → 饮食 → 搜索 → 保存 | 4 |
| 记体重 | 首页 → 指标块 → 体重详情 → 记录 | 4 | FAB → 体重 → 填写 | 3 |
| 记心情 | 「我的」→ 健康档案 → 心情页 | 4 | FAB → 心情 | 2 |
| 看今日用药 | 首页 → 用药卡 → 用药页 | 3 | 首页卡内直接勾选 | 1 |

**加权平均入口深度：4.2 步 → 2.6 步（-38%）。** 心情、用药这类「顺手记一下」的动作收益最大。

### 2.3 Dock 规格

| 项 | 值 |
|---|---|
| 总高 | 74px（含 `safe-area-inset-bottom`） |
| 布局 | `grid-template-columns: 1fr 1fr 72px 1fr 1fr`，中间 72px 为 FAB 槽位 |
| 底色 | `rgba(255,255,255,.94)` + `backdrop-filter: blur(14px)` |
| 顶部分隔 | 不用 1px 线，用 `0 -6px 20px rgba(19,34,46,.05)` 柔和投影 |
| Tab 项 | 56px 高，图标 22px，文字 11·600 |
| 激活态 | 图标与文字 `teal-700`，文字字重 **800** |
| 未激活态 | `n-700`（**不是 n-500**，见 §6 实测） |
| 点击热区 | 整格可点，≥ 56×56（超 WCAG 2.5.5 的 44×44） |

### 2.4 FAB 规格

| 项 | 值 | 依据 |
|---|---|---|
| 直径 | 56px | 与 L1 焦点卡头像同尺度，形成全 App 两大「圆」锚点 |
| 底色 | `teal-600` 实底 | 全页唯一高饱和动作色 |
| 图标 | 26px 线性 plus，`stroke-width: 2.2`，纯白 | 图形对比 3.33:1，达 3:1 门槛 |
| 凸起 | `margin-top: -16px` | 超出 dock 顶边 16px，形成「舵」的视觉 |
| 阴影 | `--hx-elev-brand` | 与主按钮同档 |
| 按下 | `scale(.94)` 120ms | |
| 激活 | 旋转 135° 并淡出 | 让位给面板，避免 FAB 与面板抢焦点 |

> **⚠️ 一处刻意的取舍**：FAB 激活时是**旋转淡出**而非停留旋转成「×」。原因是面板从底部升起必然覆盖 FAB 原位，若强行让 FAB 浮在面板之上，会压住「关闭」按钮形成双重退出入口。改为淡出后，退出路径收敛为「点遮罩 / 点关闭 / Esc」三条，语义单一。

### 2.5 快记面板（Quick Log Sheet）

| 项 | 值 |
|---|---|
| 圆角 | 顶部 28px（`--hx-r-xl`），底部 0 |
| 内边距 | `8px 16px 26px` |
| 抓手 | 36×4 圆角条，`n-200`，居中，`margin: 6px auto 14px` |
| 标题 | 「记一笔」17·800 |
| 副标 | 「选一项，3 秒完成记录 · 数据自动同步给健管师」12·500 · `n-700` |
| 入口 | **4 列 × 2 行**，8 个：体重 / 血压 / 血糖 / 用药 / 饮食 / 运动 / 睡眠 / 心情 |
| 单入口 | 图标容器 48×48 `r-md 14` + 标签 12·700，整体为按钮（无外框） |
| 动效 | `translateY(102%) → 0`，320ms `--hx-ease-out` |
| 遮罩 | `rgba(19,34,46,.42)`，200ms 淡入 |
| 关闭 | 点遮罩 / 底部「关闭」按钮 44px 高 / `Esc` |

> **为什么是 8 个而不是 6 个**：6 个会排成 3×2 或 2×3，视觉重心偏左或过高；8 个 4×2 形成稳定方块，且刚好覆盖全部高频记录类型。低频项（化验单、体检）不进面板，留在「我的」。

## 3. 设计令牌

### 3.1 完全继承 v8（不改动）

teal 十档、中性十档、语义四色、八档字号与字重纪律、圆角阶梯（8/12/14/20/28/999）、阴影阶梯（elev-0/1/2/3/brand）、4px 间距栅格、三档动效时长与缓动——全部沿用 `style.css` 现值，**零改动**。

全局红线同样延续：

- `--hx-shadow`（34 文件 / 51 处）与 `--hx-bg`（32 文件，含 `App.vue:45` 全局外壳）**值不动**
- `.hx-cat` / `.hx-ck` 被 `CarePlanView` / `SleepView` 共用，**本轮不改全局值**

### 3.2 v11 新增：品类色组（8 组）

这是本方案唯一的新增令牌。目的是让「瓷片区」与「快记面板」的 8 个记录类型**各有识别色，但整体仍是低饱和**——抄薄荷的金刚区分色逻辑，但把彩度压到可长期注视的程度。

| 类型 | Token | 前景（图标/标签） | 背景 | 实测对比度 |
|---|---|---|---|---|
| 体重 | `--hx-c-weight` / `-bg` | `#0b7a66` | `#e3f6ef` | **4.69** ✅ |
| 血压 | `--hx-c-bp` / `-bg` | `#a8243a` | `#fde7ea` | **5.97** ✅ |
| 血糖 | `--hx-c-sugar` / `-bg` | `#8a5c00` | `#fff3da` | **5.28** ✅ |
| 用药 | `--hx-c-med` / `-bg` | `#2c4f8f` | `#e9f0fd` | **7.00** ✅ |
| 饮食 | `--hx-c-diet` / `-bg` | `#0b7a66` | `#eefaf4` | 4.98 ✅ |
| 运动 | `--hx-c-move` / `-bg` | `#1f7a63` | `#e4f6f1` | **4.66** ✅ |
| 睡眠 | `--hx-c-sleep` / `-bg` | `#5b3cc4` | `#ece7ff` | **6.04** ✅ |
| 心情 | `--hx-c-mood` / `-bg` | `#b03060` | `#ffe8f0` | **5.25** ✅ |

> 全部 ≥ 4.5:1，可直接用于 11–12px 标签文字。**注意体重/运动两组的 4.66–4.69 是贴着下限的**，后续若调色只能变深不能变浅。

### 3.3 ⚠️ 对 v8 的一处修正：主按钮底色

实测发现 v8 §4「按钮」表格中规定的**主按钮 = `teal-600` 实底 + 白字 13·700**，对比度只有 **3.33:1**，**不满足 WCAG AA 对正文的 4.5:1 要求**（13px 不构成「大字」，不适用 3:1 豁免）。

| 方案 | 对比度 | 结论 |
|---|---|---|
| 白 on `teal-600`（v8 现值） | 3.33 | ❌ FAIL |
| 白 on **`teal-700`** | **5.26** | ✅ PASS，采用 |
| 白 on `teal-800` | 7.10 | ✅ 可用作按下态 |

**v11 规定**：主按钮底色改 `teal-700`，hover `teal-800`，与 `teal-600` 的视觉差异极小（同一色相相邻一档），但可读性达标。此项建议同步回写 v8。

## 5. 四屏信息架构

**首屏预算（沿用 v8 的算术）**：视口 844 − 状态栏 46 − Dock 74 = **724px 可用**，扣页面 padding 后可堆叠 **672px**。

### 屏 1 · 首页

| 顺序 | 模块 | 高度 | 层级 |
|---|---|---|---|
| 1 | 状态栏 | 46 | — |
| 2 | 顶栏（左上 Logo + 右上铃铛） | 48 | — |
| 3 | **L1 健管师焦点卡** | 112–120 | L1（全 App 唯一深色块） |
| — | 焦点后留白 | 24 | |
| 4 | L2 今日待办（单卡 + 卡内折叠行） | ~256 | L2 |
| — | 间距 | 20 | |
| 5 | L3 健康速记横滑（4 格） | 80 | L3 |

屏 1 实测占用约 **690px**（焦点卡文案两行时），仍在 724 内 → **首屏刚好收在速记区，体重目标卡留给第二屏**。这是刻意的：薄荷的问题就是屏 1 塞太满。

**屏 2**：体重目标卡 → 今日指标 2×2 → 最近报告。

> 体重目标卡（`.goal`）是本次从薄荷引入的**新模块**：大数值 28·900 + 目标差额 + 进度条 + 「起始 / 已减 / 天数」三要素。慢病人群对「趋势与达成」的感知远强于单点数值。

### 屏 2 · 健康

| 顺序 | 模块 | 说明 |
|---|---|---|
| 1 | 健康分环形卡 | **本屏唯一焦点**，尺度最大（92px 环 + 28px 数值） |
| 2 | 指标总览瓷片区 | 3×2：体重 / 血压 / 空腹血糖 / 心率 / 睡眠 / 步数 |
| 3 | 体重趋势卡 | SVG 折线 + 目标虚线 + 图例 |
| 4 | 最近记录时间线 | 4 行 |

> **折线的语义方向**：y 轴向下 = 数值下降。起点 68.5kg 在上，终点 64.2kg 在下，目标 62.0kg 的虚线必须在**终点之下**。早期版本画反了（虚线在曲线上方，等于「目标比现在更重」），已修正。

### 屏 3 · 发现

搜索框 → 4 个 Tab（推荐 / 关注 / 科普 / 圈子）→ 单列内容卡（封面 118px + 标题 + 摘要 + 元信息）。

**一屏只放 2.5 张卡**，刻意留白。薄荷「发现」页被批的点正是密度过高、视线无处落脚。

### 屏 4 · 我的

用户卡（60px 头像 + 会员标签 + 疾病标签 + 健管师与陪伴天数）→ 三列统计（连续打卡 / 累计记录 / 健康分）→ 「我的档案」4 行 → 「服务与设置」4 行。

行高 52px，卡片圆角 28px（`--hx-r-xl`）——**「我的」页允许比首页更圆润**，因为这里没有信息密度压力，圆润 = 亲和。

以下为实测值，非估算。判定基准：正文 4.5:1，大字（≥18.66px bold 或 ≥24px regular）3:1，**非文本 UI 组件与图形 3:1**。

| 白字 on `teal-700`（焦点卡主文） | 5.26 | ✅ |

| `teal-700` 正文 / 链接 on 白 | 5.26 | ✅ |
| `n-700` 次级正文 on 白 | 5.57 | ✅ |
| `n-700` on `n-50` | 5.31 | ✅ |
| `n-700` on `n-100` | 5.03 | ✅ |
| `n-800` on 白 | 8.95 | ✅ |
| `n-900` on 白 | 16.20 | ✅ |
| 白字 on `teal-700`（修正后主按钮） | 5.26 | ✅ |
| 白字 on `danger-text`（计数徽章） | 7.05 | ✅ |
| 品类色 8 组 on 各自浅底 | 4.66–7.00 | ✅ |
| FAB 白加号 on `teal-600`（图形） | 3.33 | ✅（≥3:1） |
