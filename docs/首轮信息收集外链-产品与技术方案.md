## 0. 一句话

驾驶舱一键生成**可转发链接**（微信打开即可填），客户提交后系统**自动建档并写入首轮采集字段**；替代健管师在微信里粘贴空白模板、再人工回填档案。

---

## 1. 背景与问题

### 1.1 现况（截图还原）

漠雪老师首次沟通时，在微信发送一段固定话术，请客户回复：

| # | 微信模板项 | 说明 |
|---|---|---|
| 1 | 姓名 | |
| 2 | 年龄 | |
| 3 | 身高 | |
| 4 | 体重 | |
| 5 | 饮食情况 | 自由文本 |
| 6 | 睡眠情况 | 自由文本 |
| 7 | 是否运动 | 自由文本 |
| 8 | 历史病史 | 自由文本 |
| 9 | 目前在吃药物/保健品 | 自由文本 |
| 10 | 最希望调理改善的是什么 | 自由文本 |

另附舌诊拍照规范、体围测量与体态三视图说明（**本期不做入库，仍可微信收图**）。

### 1.2 痛点

| 痛点 | 影响 |
|---|---|
| 信息在聊天记录里 | 健管师要二次抄录进系统，易漏、难检索 |
| 无手机号/性别 | 与现网建档 API 不齐，无法一键落库 |
| 与正式首诊问卷脱节 | 完整首诊过重；首轮只需「够建档 + 够出方案草稿」的薄采集 |

### 1.3 目标

| # | 目标 |
|---|---|
| G1 | 驾驶舱（含对话建档路径）可**一键生成外链**，复制后发微信 |
| G2 | 客户**免登录**打开 H5，填完提交即建档（本机构 membership + 基础档案） |
| G3 | 字段写入现有档案/体征体系，驾驶舱立即可见该患者并可「生成方案」 |
| G4 | 链接有过期、一次性/可限次、租户+机构隔离，防扫库 |
| G5 | 首期**不做**照片上传；文案可提示「舌诊/体态照请另发微信」 |

### 1.4 非目标（本期）

- 舌诊 / 体围 / 体态照上传与中医舌象分析
- 替代完整 B 端首诊问卷（减重全量模块）
- 强制 C 端注册 / 激活码（可后置：建档后另发激活）
- 短信 OTP、微信 OAuth 强绑定
- 多租户公开落地页品牌定制（先用机构名 + Healix 默认皮）

## 2. 产品形态

### 2.1 角色与主路径

```text
漠雪（驾驶舱）                客户（微信）
     │                            │
     │ 点「发首轮收集链接」          │
     │ → 复制短链 / 口令            │
     ├───────────────────────────►│ 打开 H5
     │                            │ 填写 → 提交
     │◄── 驾驶舱出现新患者 / 待办 ──┤ 建档落库
     │ 打开患者 → 生成方案 …        │
```

### 2.2 驾驶舱入口（B）

| 入口 | 行为 |
|---|---|
| 机构会话 chip / 快捷：「发首轮收集」 | 创建外链 → 气泡展示短链 +「复制链接」「复制话术」 |
| 对话：「帮我生成一个建档收集链接」 | 同能力 `INTAKE_LINK` / `CREATE_ARCHIVE` 延伸 |
| 已有患者焦点 | **不走本链路**（已建档用首诊/待补）；本链路仅「尚未有人」 |

复制话术示例：

> 您好，请点击链接填写基础健康信息（约 2 分钟），提交后我会据此为您整理方案：  
> https://…/i/xxxxxxxx  
> 舌诊与体态照片请按之前说明另发微信即可。

### 2.3 客户填写页（公开 H5）

单页、手机优先，分块：

1. **建档必要**：姓名*、性别*、手机号*、年龄*（或出生年份*）
2. **体征**：身高*（cm）、体重*（kg）
3. **生活与诉求**（均可长文本，标「选填」或按漠雪习惯全必填——**本期默认与微信模板一致：除建档必要外，原 10 项中的生活/病史/诉求为必填**，避免交白卷）
4. **底部**：隐私说明一句 + 提交

提交成功页：

- 「已提交，健管师会尽快与您联系」
- **不再展示**可改链接（防重复刷）；同一 token 再次打开 → 「本链接已使用或已过期」

### 2.4 健管师侧结果

| 结果 | 说明 |
|---|---|
| 新 `people` + 本机构 membership | 等同极简建档 |
| 体征 | 身高、体重写入 vitals（来源 `INTAKE_LINK`） |
| 档案元数据 | 饮食/睡眠/运动/病史/用药保健品/诉求写入 metadata |
| 驾驶舱 | 左栏可搜到；建议自动 `FOCUS` 或「今日优先」出现「新提交·待出方案」类提示（P1 可做成轻量待办） |
| 通知 | 本期：下次打开驾驶舱可见；P1：站内铃铛 |

## 3. 字段设计

### 3.1 表单字段 ↔ 系统落点

| 表单字段 | 必填 | 落点 | 备注 |
|---|---|---|---|
| 姓名 | ✓ | `people_profile.display_name` | |
| 性别 | ✓ | `people_profile.gender` | 微信模板无；建档 API 必需，表单补「男/女」 |
| 手机号 | ✓ | `people_profile.mobile` + `SELF` | 微信模板无；建档与触达必需 |
| 年龄 | ✓ | → `birthday` | 见 §3.2 |
| 身高 cm | ✓ | vital `HEIGHT` | |
| 体重 kg | ✓ | vital `WEIGHT` | |
| 饮食情况 | ✓ | metadata `basic.diet.note`（或 preference+note） | 自由文本，不做枚举强迫 |
| 睡眠情况 | ✓ | metadata `basic.sleep.note` | |
| 是否运动 | ✓ | metadata `basic.exercise.note` | |
| 历史病史 | ✓ | metadata 既往史文本路径（与档案「疾病史」对齐的现有 code；若无则 `basic.medicalHistory.note` 种子） | |
| 药物/保健品 | ✓ | 文本进 metadata `basic.medicationNote`；**不**自动拆成用药医嘱行 | 人工可后补结构化用药 |
| 最希望改善 | ✓ | metadata 诉求 / `goals` 文本 | 供方案生成引用 |

### 3.2 年龄 → 生日

现网 `createArchive` 要 `LocalDate birthday`。本期约定：

- 表单收集**年龄（整数岁）**
- 落库：`birthday = 今天 - age 年`，月日取 `01-01`（或取提交日的月日，产品选 **01-01** 更稳定）
- 档案标记 `birthdayApprox=true`（metadata 或 profile 扩展字段），健管师后续可在档案页改准确生日

可选增强（同迭代若成本低）：同时问「出生年份」，优先用年份 + `01-01`。

### 3.3 查重

提交时走与 B 建档相同规则：

1. `duplicates(name, birthday, mobile)`  
2. 同号已在本机构 → **不新建**，返回「您已在本机构建档，请联系健管师」；token 标已用  
3. 同号需确认 → 外链场景**无法人审点选**：策略为 **409 + 文案「请联系健管师确认」**，token 保持可用一次或改为作废由健管师重发（**定稿：token 不作废，允许改手机号重提；若确定同人则健管师侧挂接**）  
4. 无冲突 → `createArchive` + 写体征/元数据

## 4. 技术方案

### 4.1 核心对象：`intake_collect_link`

| 字段 | 说明 |
|---|---|
| id | 业务主键 |
| tenant_id / org_id | 隔离 |
| created_by_staff_id | 发链健管师 |
| token | 高熵随机（URL-safe，≥22 字符） |
| status | `OPEN` / `SUBMITTED` / `EXPIRED` / `REVOKED` |
| expire_at | 默认 **72h** |
| people_id | 提交成功后回填 |
| payload_snapshot | 提交原文 JSON（审计） |
| gmt_* | |

唯一：`uk_token`；索引：`(org_id, status, gmt_created)`。

### 4.2 API

**B 端（需登录 + 机构）**

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/b/v1/intake-collect-links` | 创建链接；body 可空或 `{ expireHours?: number }` |
| GET | `/api/b/v1/intake-collect-links/{id}` | 状态、短链、是否已提交、peopleId |
| POST | `/api/b/v1/intake-collect-links/{id}/revoke` | 作废 |
| GET | `/api/b/v1/intake-collect-links?status=OPEN` | 我发出的未完成（可选） |

创建响应示例：

```json
{
  "id": "...",
  "token": "xK9...",
  "url": "https://{user-host}/i/xK9...",
  "expireAt": "2026-11-06T12:00:00",
  "copyText": "您好，请点击链接填写…"
}
```

**公开端（无登录，限流）**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/public/v1/intake-collect/{token}` | 回显机构名、健管师称呼、过期态；**不**回租户内部 id |
| POST | `/api/public/v1/intake-collect/{token}/submit` | 提交表单 → 建档+写数 |

Submit body 对齐 §3.1；成功返回 `{ peopleIdMasked, message }`（peopleId 可不回给客户，仅 message）。

限流：同 IP / 同 token 提交 ≤ 5 次/小时；token 仅允许 **一次成功提交**。

### 4.3 服务编排（提交）

```text
validate token OPEN & not expired
validate fields
normalize mobile / gender / birthdayFromAge
duplicates check → 冲突则 BusinessException
createArchive(org, name, null, null, null, gender, birthday, mobile, SELF, false, systemOrStaffActor)
write HEIGHT/WEIGHT vitals (source=INTAKE_LINK, linkId)
upsert metadata notes
mark link SUBMITTED + people_id + snapshot
optional: create lightweight workspace task PLAN_CREATE or notify cockpit
```

`actorAccountId`：用发链健管师账号（链接上已有 `created_by_staff_id` → account），审计记「客户经外链提交」。

### 4.4 前端

| 端 | 改动 |
|---|---|
| `frontend-admin` 驾驶舱 | chip「发首轮收集」；气泡展示 url + 复制；`CALL_API` 或直调创建 API |
| `frontend-user` 或独立轻页 | 路由 `/i/:token`；Vant 表单；成功态 |
| 后端 | `health-core` 领域服务 + `health-app` B/Public Controller |

公开页部署：与 C 端同域或 `m.` 短域，便于微信内打开；路径短。

### 4.5 Agent 能力（可选同迭代）

- Capability：`INTAKE_LINK`（机构会话可用）
- 话术命中：「发收集链接」「首轮问卷链接」「让客户填资料」
- 成功动作：展示复制按钮（前端本地 clipboard），不必 `FOCUS_PATIENT`（尚无 people）

### 4.6 与现有首诊关系

| 层级 | 定位 |
|---|---|
| **本外链** | 获客首轮薄采集 + 建档 |
| **B 首诊问卷** | 入组后结构化深采（减重模块等） |
| **评估问卷请求** | 已建档患者病种评估，需登录 C | 

外链提交**不**自动等同「首诊已完成」；仅减少建档前摩擦。健管师可在档案页看到首轮文本，再决定是否开正式首诊。

## 5. 安全与合规

| 项 | 策略 |
|---|---|
| Token | 不可枚举；HTTPS only |
| 租户隔离 | token → org；禁止跨机构写入 |
| PHI | 公开 GET 不返回他人数据；仅机构展示名 |
| 隐私 | 页脚「提交即同意由 XX 机构为健康管理之目的处理资料」 |
| 日志 | 提交审计；snapshot 仅 B 端授权可见 |
| 微信 | 内置浏览器打开 H5；不做微信登录 |

## 6. 验收（漠雪）

1. 驾驶舱一点生成链接，复制发微信，客户手机打开可填。  
2. 客户提交后，机构患者列表/驾驶舱能搜到该人，有身高体重与文本备注。  
3. 同一链接第二次打开不可再改库。  
4. 72h 过期后打开有明确提示。  
5. 全程无需客户注册 App。
