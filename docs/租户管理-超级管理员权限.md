## 1. 背景与目标

### 1.1 业务背景

Healix 采用 **Platform → Tenant → Organization** 三级模型。平台侧由 **Ops（超级管理员）** 负责 SaaS 租户的开通与初始运营账号投放；租户开通后，B 端 **租户管理员（TENANT_ADMIN）** 自行建机构、邀员工、发患者邀请码。

本方案只覆盖 **Ops 超管在租户与 B 端账号层面的治理能力**，不涉及 C 端患者、PHI 检索、机构内业务配置。

### 1.2 本期目标（In Scope）

| # | 能力 | 说明 |
|---|---|---|
| 1 | **开通租户** | 创建 `tenant` 记录；**Ops 侧不创建默认机构** |
| 2 | **注册租户下 B 端账号** | 创建 `staff_account` + `staff_profile`（绑定 `tenant_id`） |
| 3 | **授予租户管理员** | 为指定 Staff 写入 `staff_role_binding(TENANT_ADMIN)`，**与机构解耦** |
| 4 | **查询租户下账号列表** | 分页列出该租户 Staff 及角色、状态 |
| 5 | **租户列表（极简）** | `GET /tenants`，供前端选租户 + `hasTenantAdmin` 告警 |

### 1.3 非目标（Out of Scope）

- 患者明文检索（已有 `GET /api/ops/v1/patients/search`，另文描述）
- Ops 账号 CRUD、MFA、短信登录
- 租户停用/套餐/配额强阻断（表字段预留，本期不做）
- Ops 侧创建默认机构（运营反馈无用且需删除，**一律由 B 端 TENANT_ADMIN 建机构**）
- 机构内角色（CARE_MANAGER / DOCTOR）的 Ops 代配（由 B 端租户管理员分配；`ORG_ADMIN` 已废弃）
- 撤销 TENANT_ADMIN、停用 B 端账号（P2）
- 首登强制改密（P2）

## 2. 与现有实现的关系

### 2.1 已实现

| 能力 | 接口 | 实现位置 |
|---|---|---|
| Ops 登录 | `POST /api/ops/v1/auth/login` | `OpsPortalController` |
| 开通租户（捆绑首管） | `POST /api/ops/v1/tenants` | `TenantProvisionService.provision()` |
| 开通审计 | action=`TENANT_CREATE` | `AuditService` |
| Ops Bootstrap | 启动创建 `opsadmin` | `BootstrapRunner` |

当前 `provision()` 行为（**待改造**）：Tenant → 默认 Organization → StaffAccount → StaffProfile → StaffOrgBinding → StaffRoleBinding(TENANT_ADMIN)。

### 2.2 待补齐

| 能力 | 现状 |
|---|---|
| 统一 `POST /tenants`（可选首管，不建默认机构） | 未改造 |
| 单独注册租户下 Staff | 无 API |
| 单独授予 TENANT_ADMIN | 无 API（仅随开通写入） |
| 租户下 Staff 列表 | 无 API / 无 Mapper 查询 |
| 租户列表 + `hasTenantAdmin` | 无 API |
| B 端 TENANT_ADMIN 零机构绑定时建机构 | `POST /orgs` 已仅需角色，需冒烟验证 |

### 2.3 演进策略

- **改造**现有 `POST /tenants` 为**单一入口**：body 用 `initialAdmin` 有无区分「仅开租户」与「快捷开通」；**不新增** `POST /tenants/create`。
- **默认主流程**为快捷开通（租户 + 首管 + TENANT_ADMIN）；分步流为次要（先开空租户 → 注册 → 授权）。
- **Ops 流程不再创建默认机构**；机构由 B 端 TENANT_ADMIN 登录后 `POST /api/b/v1/orgs` 创建。
- 服务层收敛到 `OpsTenantAdminService`（新建），`TenantProvisionService` 改为薄封装或废弃并迁移调用方。

## 3. 角色与权限

### 3.1 Ops 平台角色（`ops_account.role_code`）

| 角色 | 本期权限 |
|---|---|
| `SUPER_ADMIN` | 租户开通、Staff 注册、角色授予、租户/账号列表（**读写**） |
| `OPERATOR` | 租户列表 + 账号列表（**只读**）；**禁止** POST/PUT/PATCH |
| `AUDITOR` | 仅审计查询（本期无审计 UI；写接口一律 403） |

P1 实现：**写接口**（POST）在 Service 层校验 `roleCode == SUPER_ADMIN`；读接口（GET）允许 SUPER_ADMIN、OPERATOR；AUDITOR 本期可不开放本域读接口。

### 3.2 B 端租户管理员（`staff_role_binding.role_code`）

| 角色 | `org_id` | 含义 |
|---|---|---|
| `TENANT_ADMIN` | **NULL** | 租户级管理员；可管理租户下全部机构 |

约束：

- 同一 `staff_id` **至多一条** `TENANT_ADMIN`（`uk_staff_role_org`）。
- **允许多名** TENANT_ADMIN 共存于同一租户。
- 允许租户 **暂时零** TENANT_ADMIN；Ops UI 标红「未配置管理员」（见 §5.5）。
- 撤销 TENANT_ADMIN 及「至少留 1 名」校验：**本期不做**。

### 3.3 认证

- 入口：`/api/ops/v1/**`
- JWT：`aud=ops`，claims 含 `accountId`、`roleCode`
- 与 B/C Token **禁止串用**

### 3.4 B 端依赖（Grill Q12）

TENANT_ADMIN **可以没有任何** `staff_org_binding`。登录后 `currentOrgId` 可为 null。

- **必须保证**：`POST /api/b/v1/orgs` 在 `currentOrgId=null` 时仍可用（当前仅校验 `TENANT_ADMIN` 角色，符合预期）。
- **建议（P1-e 冒烟）**：建机构后可选写入 `staff_org_binding` 并设为 default，便于后续切换机构；**非 Ops 授权流程职责**。
- Ops **授予** TENANT_ADMIN 时 **不** 自动绑机构、**不** 依赖机构是否存在。

## 4. 领域模型与数据表

### 4.1 涉及表

```text
tenant                    # 租户
organization              # 机构（Ops 不创建；B 端 TENANT_ADMIN 创建）
staff_account             # B 端登录账号（平台级 username 唯一）
staff_profile             # B 端人员档案（tenant_id 归属）
staff_org_binding         # 人员-机构（Ops 注册时可选；非授权前置条件）
staff_role_binding        # 人员-角色（TENANT_ADMIN 时 org_id=NULL）
audit_log                 # 操作审计
```

### 4.2 关键字段与约束

| 表 | 关键约束 | 说明 |
|---|---|---|
| `tenant` | `uk_tenant_code` | 租户编码全局唯一 |
| `staff_account` | `uk_staff_username` | B 端用户名 **全局唯一**；UI 建议 `{tenantCode}_` 前缀 |
| `staff_profile` | `uk_staff_account` | 一个登录账号对应一个 Staff 档案 |
| `staff_profile` | `idx_staff_tenant` | 列表查询按 tenant_id |
| `staff_role_binding` | `uk_staff_role_org` | 同 staff + role + org 不重复 |

### 4.3 列表查询视图（逻辑）

```text
StaffAccountListItem {
  staffId, accountId, username, displayName, mobile?, title?,
  status, roles[], defaultOrgId?, createdAt
}

TenantListItem {
  tenantId, code, name, status, createdAt,
  hasTenantAdmin    // 是否存在任意 TENANT_ADMIN 绑定
}
```

`hasTenantAdmin` 判定：该租户下 **存在至少一条** `staff_role_binding.role_code = TENANT_ADMIN`（关联未删 staff）。

## 5. API 设计

统一前缀：`/api/ops/v1`  
统一响应：`ApiResult<T>`（`code=0` 成功）

### 5.1 开通租户（统一入口）

`POST /tenants`

**Request**

```json
{
  "code": "acme-health",
  "name": "爱康健康管理",
  "initialAdmin": {
    "username": "acme_admin",
    "password": "ChangeMe123!",
    "displayName": "张三",
    "mobile": "13800000000",
    "title": "运营负责人",
    "grantTenantAdmin": true,
    "bindDefaultOrgId": null
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| code | 是 | 全局唯一 |
| name | 是 | 展示名 |
| initialAdmin | 否 | **省略** = 仅创建租户（空租户，`hasTenantAdmin=false`） |
| initialAdmin.username / password | 有 initialAdmin 时必填 | 全局唯一 username |
| initialAdmin.grantTenantAdmin | 否 | 默认 **true**（快捷开通语义） |
| initialAdmin.bindDefaultOrgId | 否 | 若传则写 `staff_org_binding`；须属于该 tenant 下已有机构 |

**Response**

```json
{
  "code": 0,
  "data": {
    "tenantId": 1,
    "staffId": 100,
    "accountId": 200,
    "hasTenantAdmin": true
  }
}
```

仅开租户时 `staffId` / `accountId` 为 null，`hasTenantAdmin=false`。

**规则**

- **不创建**默认机构（无 `createDefaultOrg` 字段）。
- `initialAdmin` 存在时：创建 staff + profile；若 `grantTenantAdmin=true` 写入 TENANT_ADMIN。
- 写审计：`TENANT_CREATE`（detail 含是否含 initialAdmin、hasTenantAdmin）

**错误码**：409 重复 code / username；400 非法 bindDefaultOrgId

---

### 5.2 注册租户下 B 端账号

`POST /tenants/{tenantId}/staff-accounts`

**Request**

```json
{
  "username": "acme_admin01",
  "password": "ChangeMe123!",
  "displayName": "张三",
  "mobile": "13800000000",
  "title": "运营负责人",
  "grantTenantAdmin": false,
  "bindDefaultOrgId": null
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| username | 是 | 全局唯一；建议 `{tenantCode}_` 前缀 |
| password | 是 | 长度 ≥ 8，BCrypt |
| grantTenantAdmin | 否 | 默认 **false**；true 时同事务写入 TENANT_ADMIN |
| bindDefaultOrgId | 否 | 可选绑机构，与授权 **解耦** |

**Response**

```json
{
  "code": 0,
  "data": {
    "staffId": 100,
    "accountId": 200,
    "tenantId": 1,
    "grantedTenantAdmin": false
  }
}
```

**规则**

- 校验 tenant 存在且未删
- 写审计：`STAFF_ACCOUNT_CREATE`

---

### 5.3 授予租户管理员

`POST /tenants/{tenantId}/staff/{staffId}/roles/tenant-admin`

无 body；**幂等**（已存在则 200）。

**Response**

```json
{
  "code": 0,
  "data": {
    "staffId": 100,
    "roleCode": "TENANT_ADMIN"
  }
}
```

**规则**

- `staff_profile.tenant_id` 必须等于路径 `tenantId`
- 仅插入 `staff_role_binding(TENANT_ADMIN, org_id=NULL)`
- **不**自动创建或绑定机构
- 写审计：`STAFF_ROLE_GRANT`

---

### 5.4 查询租户下账号列表

`GET /tenants/{tenantId}/staff-accounts`

**Query**：`keyword`、`status`（ACTIVE/DISABLED）、`roleCode`、`page`（默认 1）、`pageSize`（默认 20，最大 100）

**Response**：分页 `StaffAccountListItem`（含 mobile；OPERATOR 可读，不脱敏）

**规则**

- 只读；**分页请求不写审计**
- 审计由前端 **首次进入租户「账号管理」Tab** 时触发专用接口（见 §5.6）

---

### 5.5 租户列表（P1 必做，极简）

`GET /tenants`

**Query**：`keyword`、`page`、`pageSize`（status 筛选 P2）

**Response**

```json
{
  "code": 0,
  "data": {
    "total": 1,
    "items": [
      {
        "tenantId": 1,
        "code": "acme-health",
        "name": "爱康健康管理",
        "status": "ACTIVE",
        "hasTenantAdmin": false,
        "createdAt": "2026-08-27T04:00:00Z"
      }
    ]
  }
}
```

**UI**：`hasTenantAdmin=false` 时标红「未配置管理员」（含刚创建的空租户）。

---

### 5.6 账号管理 Tab 进入审计

`POST /tenants/{tenantId}/staff-accounts/audit-view`

无 body；前端在进入账号管理 Tab **时调用一次**（非每次分页）。

写审计：`TENANT_STAFF_TAB_VIEW`（或复用 `TENANT_STAFF_LIST`，常量名实现时二选一）

## 6. 服务层设计

### 6.1 模块划分

```text
health-app
  └── web/ops/OpsPortalController
health-core
  └── ops/OpsTenantAdminService          # 核心编排 + SUPER_ADMIN 写校验
  └── tenant/TenantProvisionService      # 迁移为调用 OpsTenantAdminService 或废弃
  └── identity/IdentityService
  └── audit/AuditService
```

### 6.2 核心方法

```java
public interface OpsTenantAdminService {

    TenantCreateResult provisionTenant(ProvisionTenantCommand cmd, Long opsAccountId);

    StaffRegisterResult registerStaff(Long tenantId, RegisterStaffCommand cmd, Long opsAccountId);

    void grantTenantAdmin(Long tenantId, Long staffId, Long opsAccountId);

    PageResult<StaffAccountListItem> listStaff(Long tenantId, StaffListQuery query);

    PageResult<TenantListItem> listTenants(TenantListQuery query);

    void auditStaffTabView(Long tenantId, Long opsAccountId);
}
```

写方法入口：`requireSuperAdmin(opsAccountId)`。

### 6.3 事务边界

| 操作 | 事务 |
|---|---|
| provisionTenant | tenant [+ staff + role 若 initialAdmin] |
| registerStaff | staff_account + staff_profile [+ role 若 grantTenantAdmin] [+ org_binding 若 bindDefaultOrgId] |
| grantTenantAdmin | staff_role_binding **仅** |
| list* / auditStaffTabView | 只读 / 单条 audit insert |

### 7.1 action 常量

| 常量 | 值 | 触发时机 |
|---|---|---|
| `AUDIT_TENANT_CREATE` | `TENANT_CREATE` | 开通租户 |
| `AUDIT_STAFF_ACCOUNT_CREATE` | `STAFF_ACCOUNT_CREATE` | 注册 Staff |

| `AUDIT_TENANT_STAFF_TAB_VIEW` | `TENANT_STAFF_TAB_VIEW` | 首次进入账号管理 Tab |

## 8. 安全与校验

| 项 | 方案 |
|---|---|
| 密码 | BCrypt；`@Size(min=8)`；响应不含 hash |
| 用户名 | 全局唯一 `[a-zA-Z0-9_.-]{4,64}`；UI 提示 `{tenantCode}_` |
| 写权限 | **仅 SUPER_ADMIN**；OPERATOR/AUDITOR POST → 403 |
| 读权限 | SUPER_ADMIN + OPERATOR 可读租户/账号列表 |
| 租户隔离 | Ops 显式 `tenantId` 路径参数 |

## 10. 典型流程

### 10.1 流程 A：快捷开通（默认）

```text
Ops 登录 → POST /tenants（含 initialAdmin, grantTenantAdmin=true）
→ TENANT_ADMIN B 端登录（currentOrgId 可为 null）
→ POST /api/b/v1/orgs 创建真实机构 → 邀员工 / 发邀请码
```

### 10.2 流程 B：分步开通

```text
POST /tenants（无 initialAdmin）→ 列表标红
→ POST /tenants/{id}/staff-accounts（可多次，grantTenantAdmin 默认 false）
→ POST .../roles/tenant-admin（或与注册时 grantTenantAdmin=true 合并一步）
→ GET /tenants/{id}/staff-accounts 确认
```
