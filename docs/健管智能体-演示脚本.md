# Healix 健管智能体 · 演示脚本

| 项 | 内容 |
|---|---|
| 产品名 | Healix 健管智能体 |
| 受众 | 客户演示 / 内部评审 / 销售陪访 |
| 时长 | 完整版 12–15 分钟；最短版约 8 分钟 |
| 入口 | B 端机构工作台 → 智能驾驶舱（建议默认首页） |
| 原则 | AI 只出草稿/预填，**人确认后才生效**；不演示自动写库、自动发布 |

---

## 1. 一句话定位

健管师以**对话为主入口**，完成「看谁优先 → 判怎么做 → AI 出草稿 → 人确认落库」。

主卖点：**管理方案生成**、**检验/检查 OCR**。  
底座：机构运营闭环（优先名单、任务、提醒、随访）。

## 4. 演示脚本（口播 + 操作）

### 开场 · 约 30 秒

> Healix 健管智能体，不是挂在旁边的聊天插件，而是机构工作台的**主入口**。  
> 健管师每天打开，先看今天该处理谁，再在对话里完成提醒、随访、方案、OCR——AI 起草，人确认。

---

### 第一幕：看 · 驾驶舱开场（约 2 分钟）

**操作**

1. 登录 → 进入机构 → 落在驾驶舱  
2. 指左栏「今日优先」、中栏对话、右栏「当前焦点」  
3. 展示开场简报（LLM 或模板均可）  
4.（可选）刷新页面，说明对话/简报可续

**口播**

> 左边是今天优先名单，按人聚合。  
> 中间智能体先开口，告诉你建议先处理谁。  
> 右边是当前患者工作上下文——点人之后才亮起来。

---

### 第二幕：判 · 点人进上下文（约 2 分钟）

**操作**

1. 点左栏患者 A  
2. 看右栏：评估、档案完整度、依从、待你确认、工作台待办  
3. 等待自动追问给出「下一步建议」与动作按钮

**口播**

> 点人 = 注入上下文。智能体结合档案、依从、任务，给出可执行下一步，并带上动作卡——不是只聊天。

---

### 第三幕：做 · 动作卡 + 回执（约 2 分钟）

**操作**（按数据择一或都做）

1. C 端已激活时：点「站内提醒患者」→ 看气泡「回执：…」  
2. 点「一键创建随访待办」→ 回执 + 待办刷新  
3. 或输入「帮我起草一段随访指导」→ 点「使用随访草稿」打开抽屉预填

**口播**

> 动作落在现有业务 API 上，点一下就办，结果在对话里回执。  
> AI **不会**偷偷写库或自动办结随访——人还在环里。

---

### 第四幕：主卖点 · 制定管理方案（约 4 分钟）

**操作**

1. 对患者说「请制定管理方案」，或点能力「制定管理方案」  
2. 展示活动轨迹（思考 / 工具）  
3. 看流式正文：运动 → 饮食 → 执行 → 总结；**分节标题与字段标签加粗，正文不加粗**  
4. 点预览或右栏「待你确认」进入方案页  
5. 强调：草稿 → 人工审阅 → 再发布

**口播**

> 核心能力之一：不是甩 JSON，而是健管师可读的方案结构，边生成边展示。  
> 结果先进草稿，发布必须人过眼。

---

### 第五幕：主卖点 · OCR（约 3 分钟）

**操作**

1. 上传检验单或检查单  
2. 展示识别预填（驾驶舱卡片或跳转录入页）  
3. 故意改一处 → 确认入库  
4.（可选）到检验/检查页核对

**口播**

> 另一主卖点：检验/检查单 OCR。识别只预填，确认才落库——与方案同一原则：AI 加速，责任在人。

---

### 收尾 · 约 30 秒

> 三条记住就行：  
> 1）对话是工作台，不是插件；  
> 2）方案与 OCR 是主卖点，运营闭环是底座；  
> 3）全程人审——可上线、可追责、可规模化。

## 7. 常见问答

**和 ChatGPT 有什么不同？**  
接机构业务数据与动作（任务、提醒、方案、OCR），结果进现有系统，可审可追。

**模型挂了怎么办？**  
简报可降级模板；方案路径显式失败（不静默假方案）；OCR/业务 API 仍可用。

**数据安全？**  
租户/机构隔离；交互有审计日志；发布与写库需员工操作。
