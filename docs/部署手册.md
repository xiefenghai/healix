# Healix 线上部署手册

面向：**云厂商托管首期上线**（ECS + RDS MySQL + 云 Redis + Nginx，B 管理端 + C 端 H5 + 统一后端）。

本地开发请继续用 `scripts/start-dev.sh` + IDE 起后端，**不要**把 Vite `npm run dev` 当生产。

---

## 1. 目标架构

| 组件 | 建议 | 说明 |
|------|------|------|
| ECS（Linux，JDK 21） | 1 台起步 | 跑 Spring Boot `health-app` + Nginx 静态站 |
| RDS MySQL 8 | 托管 | 业务库；勿对公网开放 |
| 云 Redis | 托管 | 与 `spring.data.redis.*` 对齐 |
| 域名 + HTTPS | 必需 | 见下方域名约定 |
| OSS | 可选 | 大文件后续再迁；首期可省略 |
| 负载均衡 / 多实例 | 二期 | CareChat SSE 需 sticky，见第 8 节 |

```text
浏览器
  ├─ https://admin.example.com   → Nginx → frontend-admin/dist
  ├─ https://m.example.com       → Nginx → frontend-user/dist
  └─ 两域 /api/*                 → Nginx → 127.0.0.1:8080（同源反代，免跨域）
```

**域名约定（可改，全文替换即可）：**

- `admin.example.com` — B 端 / Ops（`frontend-admin`）
- `m.example.com` — C 端 H5（`frontend-user`）

## 2. 上线前检查清单

- [ ] 云账号、ECS、RDS、Redis、安全组、域名解析、证书已就绪
- [ ] 生产密钥已生成（JWT / 身份证加解密 / Ops 密码），**非仓库默认值**
- [ ] DeepSeek（或兼容网关）API Key 可用；`AGENT_LLM_ENABLED=true`（要用智能体时）
- [ ] 本机或 CI 能成功：`mvn -pl health-app -am package`、双前端 `npm run build`
- [ ] 已阅读第 7 节冒烟用例

## 3. 云资源准备

### 3.1 安全组

| 入方向 | 来源 | 用途 |
|--------|------|------|
| 80 / 443 | 0.0.0.0/0 | HTTPS（及 HTTP 跳转） |
| 22 | 运维 IP | SSH |
| **不要**放行 8080 公网 | — | 仅本机 Nginx 反代 |

RDS / Redis 仅允许 ECS 私网访问。

### 3.2 MySQL

1. 创建库：`healix`（字符集 `utf8mb4`）
2. 创建业务账号，限制来源为 ECS 私网
3. 记下：`主机`、`端口`、`库名`、`用户`、`密码`

应用启动时会按 `schema.sql` **补建缺失表**（`IF NOT EXISTS`）。生产建议：

- 首次：允许自动建表或手工执行 `backend/health-app/src/main/resources/schema.sql`
- 稳定后：将 `SPRING_SQL_INIT_MODE=never`，改走迁移流程

### 3.3 Redis

记下：`host`、`port`、`password`（无密码则空）。

### 3.4 ECS 软件

```bash
# 示例：Ubuntu / Debian 思路，按发行版调整
sudo apt update
# 安装 OpenJDK 21、Nginx；Node 仅构建机需要，生产机可只收 dist
java -version   # 需 21+
nginx -v
```

目录建议：

```text
/opt/healix/
  ├── app/                 # healix.jar + healix.env
  ├── www/
  │   ├── admin/           # frontend-admin/dist
  │   └── user/            # frontend-user/dist
  └── logs/
```

## 4. 后端部署

### 4.1 构建

在构建机或 CI：

```bash
cd backend
export JAVA_HOME=...   # JDK 21
mvn -pl health-app -am -DskipTests package
# 产物：health-app/target/health-app-*.jar（以实际文件名为准）
```

将 jar 上传到 ECS：`/opt/healix/app/healix.jar`。

### 4.2 环境变量

在 ECS 创建 `/opt/healix/app/healix.env`（**勿提交 Git**），示例见仓库 [`deploy/env.prod.example`](../deploy/env.prod.example)。

关键项：

| 变量 | 说明 |
|------|------|
| `SPRING_PROFILES_ACTIVE=prod` | 生产配置 |
| `SERVER_PORT=8080` | 仅本机监听 |
| `SPRING_DATASOURCE_URL` | `jdbc:mysql://<RDS>:3306/healix?...` |
| `SPRING_DATASOURCE_USERNAME` / `PASSWORD` | RDS 账号 |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` | 云 Redis |
| `JWT_SECRET` | ≥32 字节随机串 |
| `ID_CARD_AES_KEY` / `ID_CARD_PEPPER` | 身份证加解密 |
| `OPS_BOOTSTRAP_USERNAME` / `PASSWORD` | 首次 Ops 账号（上线后立刻改密） |
| `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` | 大模型 |
| `AGENT_LLM_ENABLED=true` | 开启智能体 |
| `AGENT_OCR_MODE` | `VISION` 或 `TEXT_LLM` |
| `SPRING_SQL_INIT_MODE` | 首期可 `always`；稳定后 `never` |

主配置见 [`backend/health-app/src/main/resources/application.yml`](../backend/health-app/src/main/resources/application.yml)。  
若未单独提供 `application-prod.yml`，用环境变量覆盖即可（Spring Boot 松散绑定）。

### 4.3 systemd 常驻

示例单元：[`deploy/healix-backend.service.example`](../deploy/healix-backend.service.example)

```bash
sudo cp deploy/healix-backend.service.example /etc/systemd/system/healix-backend.service
# 编辑 User、路径、EnvironmentFile
sudo systemctl daemon-reload
sudo systemctl enable --now healix-backend
sudo systemctl status healix-backend
curl -sS http://127.0.0.1:8080/actuator/health
```

### 4.4 CORS

推荐 **Nginx 同源反代 `/api`**，浏览器不跨域。  
若必须前后端不同域，需收紧 [`CorsConfig.java`](../backend/health-app/src/main/java/com/healix/config/CorsConfig.java) 白名单为生产 HTTPS 域名（去掉局域网通配）。

## 5. 前端部署（B + C）

### 5.1 构建

```bash
cd frontend-admin && npm ci && npm run build
# 产物：frontend-admin/dist

cd frontend-user && npm ci && npm run build
# 产物：frontend-user/dist
```

上传：

```bash
rsync -av --delete frontend-admin/dist/ user@ecs:/opt/healix/www/admin/
rsync -av --delete frontend-user/dist/  user@ecs:/opt/healix/www/user/
```

前端请求路径为 **相对路径** `/api/...`。开发态 Vite 代理仅本地有效；生产由 Nginx 反代，**无需**再配 `VITE_API_BASE`（当前代码亦无强制依赖）。

管理端 SSE：仅 `import.meta.env.DEV` 时直连 `:8080`；生产走同源 `/api`，与反代一致。

### 5.2 Nginx

完整示例：[`deploy/nginx-prod.example.conf`](../deploy/nginx-prod.example.conf)

要点：

- 两个 `server`：admin / m
- `location /`：SPA `try_files $uri $uri/ /index.html`
- `location /api/`：反代本机 `8080`
- SSE：`proxy_buffering off`、`proxy_read_timeout` 拉长、`X-Accel-Buffering: no`
- TLS：证书路径按云厂商或 Let’s Encrypt 填写

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## 6. 发布与回滚

### 6.1 推荐发布顺序

1. 备份当前 jar 与两个 `dist` 目录
2. 上传新 jar → `systemctl restart healix-backend` → 检查 `/actuator/health`
3. 同步新 `dist` → `nginx reload`（静态可先发）
4. 执行第 7 节冒烟

### 6.2 回滚

```bash
# 后端
sudo systemctl stop healix-backend
cp /opt/healix/app/healix.jar.bak /opt/healix/app/healix.jar
sudo systemctl start healix-backend

# 前端：恢复上一版 dist 备份后 reload nginx
```

### 6.3 可选：本地/CI 打包

```bash
mvn -f backend/pom.xml -pl health-app -am -DskipTests package
(cd frontend-admin && npm ci && npm run build)
(cd frontend-user && npm ci && npm run build)
# 再 rsync / scp 到 ECS
```

## 7. 上线冒烟

| # | 端 | 操作 | 期望 |
|---|-----|------|------|
| 1 | Admin | 打开 `https://admin.example.com/entry` | 入口页正常 |
| 2 | Ops | 超管登录 | 进 Ops 门户 |
| 3 | B | 租户 / 机构工作台登录、选机构 | Token 互不串用 |
| 4 | B | 驾驶舱 →「今日建议」 | SSE 流式有回复，刷新后历史仍在 |
| 5 | B | 点患者 → 生成方案 / OCR | 草稿/预填；确认才落库 |
| 6 | C | 打开 `https://m.example.com` | H5 可登录、选患者卡 |
| 7 | C | 站内消息 / care-chat（若启用） | 长连接或轮询兜底正常 |
| 8 | — | 中途切会话 / 关页 | 后端无刷屏把 emitter 已关闭误报成 LLM 失败 |

默认 Ops 账号以环境变量为准；**上线后立即修改密码**。

## 8. 多实例与 SSE（二期）

CareChat 等进程内广播在多实例下会丢推送。二期加机器时：

1. 参考 [`deploy/nginx-care-chat-sse.example.conf`](../deploy/nginx-care-chat-sse.example.conf) 做 **ip_hash / sticky**
2. Agent `/api/b/v1/agent/chat/stream` 同样需要长超时 + 关闭缓冲
3. 会话落库已在 DB；推送通道才依赖粘滞

首期 **单 ECS 单 JVM** 可跳过本节。

## 9. 安全与运维注意

- 密钥、API Key、数据库密码只放 ECS 环境文件或密钥管理服务
- 生产关闭或限制 Swagger（`/swagger-ui.html`、`/v3/api-docs`）公网访问
- Actuator：仅暴露 `health`；Prometheus 等走内网
- 定期备份 RDS；关注 DeepSeek 额度与限流
- 日志目录 `/opt/healix/logs`，保留滚动策略
- Influx / Zipkin 默认可关（`INFLUX_ENABLED=false`），非演示必备

## 10. 与本地开发的区别

| | 本地 | 线上 |
|--|------|------|
| 前端 | `npm run dev`，Vite 代理 `/api` | `npm run build` + Nginx 静态 |
| 监听 | `start-dev.sh` 可用 `0.0.0.0` 给局域网 | 公网只暴露 443 |
| 后端 | IDE / `mvn spring-boot:run` | jar + systemd |
| 配置 | `application-local.yml` / `.env` | `healix.env` + prod 变量 |
| SSE | DEV 可直连 `:8080` | 必须走 Nginx `/api` |

## 12. 故障速查

| 现象 | 排查 |
|------|------|
| 页面开得开，接口 502 | `systemctl status healix-backend`；`curl 127.0.0.1:8080/actuator/health` |
| 登录跨域 / CORS | 是否未走同源 `/api`；检查 Nginx `proxy_pass` |
| 对话一直转圈无回复 | Nginx 是否缓冲 SSE；超时是否过短；`AGENT_LLM_ENABLED` 与 API Key |
| 另一台电脑局域网访问不了开发机 | 开发问题：`start-dev.sh` 须 `--host 0.0.0.0`，且关掉 Clash TUN；与本手册线上无关 |
| 刷新后会话丢失 | DB 连通性；`/api/b/v1/agent/sessions/current` 是否有数据 |
