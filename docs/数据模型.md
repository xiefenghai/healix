## 1. 设计原则

1. **共享库 + 行级租户**：业务表带 `tenant_id`；平台级表（`tenant`、`ops_account`、部分全局配置）不强制租户拦截。
2. **患者租户隔离**：`people_profile` / `people_account` / `people_identity` 等均带 `tenant_id`；跨租户同一真人 = 两条独立 people。
3. **C/B/Ops 账号分离**：三套登录表（`people_account` / `staff_account` / `ops_account`），互不外键关联。
4. **双主键**：`pk_id` AUTO_INCREMENT 物理主键；`id` 雪花业务主键；外键（`tenant_id`/`org_id`/`people_id`/`staff_id` 等）指向对方 **`id`**。
5. **软删与审计时间**（全表统一）：
   - `is_deleted`：0 未删除 / 1 已删除
   - `gmt_created` / `gmt_modified`：`DATETIME`
   - `gmt_deleted`：未删默认 `9999-12-31 23:59:59`；删除时写当前时间
   - 业务唯一键含 `gmt_deleted`，便于软删后复用 username/code
6. **时间**：库表公共字段用 `DATETIME`（秒）；业务时刻字段同为 `DATETIME`；应用层 `LocalDateTime`。
7. **P1 / P2**：下文标注阶段；`schema.sql` 中 P2 表一并建好，便于演进，应用层 P1 不使用即可。

应用约定：插入前 `EntityMeta.onCreate(entity)`（写雪花 `id` + 公共字段）；更新 `EntityMeta.onUpdate`；软删 `EntityMeta.onSoftDelete`。

### 1.1 租户拦截白名单（建议）

不自动追加 `tenant_id` 条件的表：

- `tenant`
- `ops_account`
- `audit_log`（按查询条件显式过滤）
- 字典/飞书类全局配置（若有）

其余带 `tenant_id` 的表走拦截器（含全部 `people_*`）。

## 2. ER 关系（逻辑）

```text
tenant 1───* organization 1───* org_invite_code
                │
                ├──* staff_org_binding *── staff_profile ──1 staff_account
                │         │
                │         └──* staff_role_binding
                │
                ├──* care_team ──* care_team_member
                │                      ├── STAFF → staff_profile
                │                      └── PATIENT → people_profile
                │
                └──* people_org_membership *── people_profile ──0..1 people_account
                            │                      ├──* people_identity
                            │                      └──* people_basic_archive
people_care_assignment ─────┘（primary_org + primary_care_manager）

tenant 1───* vital_record *── people_profile
tenant 1───* agent_session *── people_profile | staff_profile
                └──* agent_message
                └──* agent_interaction_log

ops_account ──▶ audit_log（操作者可三端）
```

## 4. 枚举约定

| 字段 | 取值 |
|---|---|
| `tenant.status` | `ACTIVE` / `SUSPENDED` / `CLOSED` |
| `organization.status` | `ACTIVE` / `DISABLED` |
| `role_code` | `TENANT_ADMIN` / `CARE_MANAGER` / `DOCTOR` / `TENANT_OPERATOR`（预留）；~~`ORG_ADMIN` 已废弃~~ |
| `membership.status` | `ACTIVE` / `LEFT` |
| `invite.enabled` | 0/1 |
| `vital.metric_type` | `BLOOD_GLUCOSE` / `BLOOD_PRESSURE_SYS` / `BLOOD_PRESSURE_DIA` / `HEART_RATE` / `WEIGHT` / `STEPS` / `SLEEP_HOURS` / … |
| `agent_type` | `PATIENT` / `CARE_COPILOT` |
| `identity_type` | `ID_CARD` / `MILITARY_ID` / `HK_MACAU_PASS` / `TAIWAN_PASS` / `OTHER` |
| `care_team_member.member_type` | `STAFF` / `PATIENT` |
| `archive.source` | `B_SIDE` / `C_JOIN` |
| `audit.action` | 如 `OPS_PHI_VIEW` / `TENANT_CREATE` / `STAFF_ORG_BIND_REPLACE` / `MEMBERSHIP_JOIN` / `PATIENT_ARCHIVE_CREATE` / … |
| `portal` | `C` / `B` / `OPS` |

角色与机构范围约定（v0.2）：

- **功能角色**（`staff_role_binding`）：一律 `org_id = NULL`，只表达「能做什么」（菜单/按钮/业务操作）。
- **机构范围**（`staff_org_binding`）：表达「能进哪些机构」。
- `TENANT_ADMIN`：不依赖 binding，**隐式拥有本租户全部机构**。
- `CARE_MANAGER` / `DOCTOR`：工作台 `currentOrgId` 必须落在其 binding 内。
- `TENANT_OPERATOR`：预留（运营分析）；本期不分配。
- `ORG_ADMIN`：废弃，不再写入。

## 6. 关键完整性（应用层保证）

MySQL 可不建跨库物理 FK（便于软删与拦截器），但服务必须保证：

1. 建档 / 入组：`people_profile.tenant_id` 与当前租户一致；证件 `(tenant, type, hash)` 未被他人占用。
2. 首次 ACTIVE membership：写/更新 `people_care_assignment`。
3. 退出后若无 ACTIVE membership：care_assignment 软删或保留历史（不再清 `home_tenant_id`）。
4. 写 `vital_record`：`people_id` 必须属于写入 `tenant_id`。
5. Staff 切换工作机构：`currentOrgId` ∈ 其 `staff_org_binding`（`TENANT_ADMIN` 例外）。
6. PATIENT Agent 会话：`people_id` 必填；机构接口不可按 org 列出此类 session。
7. C 注册/登录须带 `tenantId`（账号租户内唯一）。

## 7. 与可见性矩阵的落库映射

| 数据 | 表 | 隔离键 |
|---|---|---|
| 档案 | people_profile (+ identity / basic_archive) | tenant_id + people_id |
| 体征 | vital_record | tenant_id + people_id |
| 报告 | health_report (P2) | tenant_id + people_id |
| 工单/随访 | alert_ticket / follow_up_task (P2) | tenant_id + org_id |
| 私聊 | agent_* where agent_type=PATIENT | people_id（禁止 B 列表接口） |

## 8. 初始化数据建议

P1 启动后由 Ops 手工或 flyway/seed：

1. 插入 1 个 `ops_account`（超管）。
2. 开通演示租户 + 默认机构 + 租户管理员 staff。
3. 生成邀请码供 C 端联调。

（不在 `schema.sql` 写死密码哈希，避免环境耦合。）
