# Healix C 端微信小程序上架方案

> 结论：**能上，而且可以分两步走**。
>
> - **内测（现在就能做）**：走体验版，不备案、不认证、不审核，约 15 名体验成员可用。唯一卡点是服务器域名，用**云函数代理**当天绕开。
> - **正式上架**：主体无医疗资质时走 **【工具 - 健康管理】** 类目，技术上用 **uni-app 原生化**。此时真正的 blocking 项是 **API 域名 ICP 备案** 与 **健管师对话的定性**。

---

## 一、现状盘点

`frontend-user` 是一个标准 H5 SPA，不是小程序工程。

| 项 | 现状 |
|---|---|
| 技术栈 | Vue 3.5 + Vite 8 + Vant 4 + vue-router 4 + ECharts 5 |
| 规模 | 52 个 `.vue`，约 28k 行（含 ts / css） |
| 路由 | 40+ 条，4 个 Tab（首页 / 健康 / 发现 / 我的） |
| 认证 | `Bearer Token` 存 `localStorage`，账号密码登录 |
| 部署 | nginx 静态托管（`deploy/docker/release/www/user`） |

**H5 专属依赖**（小程序中不可用）：

- `api/http.ts` — `fetch` / `Headers` / `FormData` / `localStorage` / `window.setTimeout`
- `shared/web-push.ts` — Service Worker 注册与推送订阅
- `shared/care-plan-print.ts`、`shared/management-report-print.ts` — `window.print`
- `shared/care-chat-sse.ts` — `EventSource`（小程序无此对象）
- `views/HealthDataHubView.vue`、`views/ManagementReportDetailView.vue` — ECharts
- `views/MedicationScanView.vue`、`shared/image.ts` — 图片选择与压缩

Vant 4 是 DOM 组件库，在小程序环境**一行都跑不了**；`createWebHistory` 也没有对应物。不存在"直接编译成小程序"的路径，必须改造。

## 二、内测路径：体验版（不走发布，先验证）

如果目标只是"给几个人内测"，**根本不需要上架**，走体验版即可。

### 2.1 体验版豁免了什么

| 要求 | 体验版内测 | 正式发布 |
|---|---|---|
| 小程序备案 | 不需要 | 必须 |
| 微信认证 | 不需要 | 必须 |
| 代码审核 | 不需要 | 必须 |
| 类目资质 | 不需要 | 按类目 |
| 服务器域名 | **仍需校验** | 必须 |
| 可用人数 | 约 15 名体验成员 | 全体微信用户 |

依据：工信部备案规则对"仅用于内部测试、不对外发布上架、普通用户无法搜索访问"的小程序豁免；微信官方回复确认"线上版本没有已发布的小程序，只在开发版本有体验版，那就没事"。

**顺带解掉的结**：前面担心的【工具 - 健康管理】类目资质、健管师对话定性、OCR 合规——这些全是**提审环节**才卡的东西。内测阶段一个都不用管，可以先按完整功能验证产品，等要正式上架时再做减法。

### 2.2 前提条件

- **必须是正式注册的小程序账号**，微信**测试号不行**——测试号无法上传版本、无法添加体验成员、也不支持云开发
- 个人主体可免费注册；企业主体注册后**未认证也能**开发、上传、使用体验版（认证只在正式发布时强制）
- 后端需能被公网访问（见 2.3）

### 2.3 唯一的卡点：体验版也校验服务器域名

体验版与正式版的域名校验规则一致——`request` 合法域名必须是**已 ICP 备案 + HTTPS**。
开发者工具里"不校验合法域名"只在 IDE 与真机调试时有效，**体验版二维码发给同事就会报"不在 request 合法域名列表中"**。

内测阶段三个绕开办法：

| 方案 | 成本 | 说明 |
|---|---|---|
| **A. 云函数代理**（推荐） | 0 天 | 小程序调 `wx.cloud.callFunction`，云函数出网请求 Healix 后端。云函数走微信内置通道，**不占用也不校验服务器域名**；出网可直接用 IP + 端口，无需备案 |
| **B. 微信云托管** | 2–3 天 | Spring Boot 后端容器化部署到云托管，用平台分配的默认域名，该域名可直接配置为合法域名 |
| **C. 老实备案域名** | 1–20 工作日 | 最正规，正式上线也必须用 |

**建议 A 与 C 并行**：今天就用云函数代理跑内测，同时提交域名备案。

⚠️ A / B 是开发期权宜之计，**正式上架必须切回自有已备案域名**，不要沿用云函数代理链路提审。

### 2.4 内测操作步骤

1. 注册正式小程序账号（企业主体），拿到 AppID
2. 在**微信开发者工具里点「云开发」按钮**开通环境——不要先去腾讯云控制台创建，那边建的环境小程序端用不了；弹登录页时务必选「**微信公众平台登录**」。开通前确认腾讯云账号已完成实名认证，否则会创建失败且报错不明显
3. 建云函数 `healix-proxy`，转发到 Healix 后端公网地址
4. uni-app 工程配置 AppID，上传版本
5. MP 后台「版本管理」把开发版本**选为体验版**
6. 「成员管理 → 体验成员」添加内测用户微信号（**添加后无通知，需自行通知对方**）
7. 把体验版二维码发给对方

## 三、合规准入（决定能否正式上线）

### 3.1 类目：走【工具 - 健康管理】

微信官方口径（开放社区运营回复）：

> 若非个人主体小程序涉及**记录 / 测试与健康相关内容**，建议选 **【工具 - 健康管理】** 类目；若涉及医疗相关内容，需补充医疗类目。

【工具 - 健康管理】适用于提供身高、体重等**健康管理记录**，**无医疗资质要求**——这正是 Healix 的定位。

**可以选**：【工具 - 健康管理】

**绝对不碰**（均需《医疗机构执业许可证》）：

- 【医疗服务】下全部：公立医疗机构 / 互联网医院 / 私立医疗机构 / 就医服务
- 【医疗 - 其他医学健康服务】（4 选 1 资质，含"运动检测、营养检测"类服务）

⚠️ 如果小程序里出现**医疗资讯科普**内容，微信会要求补【医疗 - 健康(资讯)服务】类目。一期不要做"健康资讯 / 科普文章"板块。

### 3.2 前置：ICP 备案（硬卡点，与前端无关）

小程序后台配置的 **request 合法域名 / uploadFile 域名 / socket 合法域名都必须是已 ICP 备案的域名**，且必须 HTTPS。

当前 `deploy/` 下的 nginx 配置均为 `.example`，**未写 `server_name`**，说明对外域名尚未确定。这是最容易被忽略、也最容易卡住上线的前置项，建议与开发并行启动（备案通常 1–20 个工作日）。

### 3.3 隐私合规（无资质主体审核最严的一环）

健康数据属于《个人信息保护法》定义的**敏感个人信息**，微信强制要求：

1. 小程序后台配置《用户隐私保护指引》，逐项声明采集的健康数据、相册 / 摄像头权限
2. 代码中调用 `wx.requirePrivacyAuthorize` 显式弹窗授权，未配置直接接口报错
3. **按需授权**——在用户点击"上传检验单"时才要相册权限，禁止启动时一次性索取全部权限
4. 禁止"拒绝即退出"式强制授权

### 3.4 功能红线

项目已有 `scripts/check-sensitive-words.mjs`（禁"处方 / 诊断 / 医嘱 / 确诊 / 治疗方案"等）。
**已确认 C 端源码中"确诊""患病风险"零命中**，合规基础很好。小程序版必须保持，并：

- 脚本扫描范围需新增小程序端目录
- 后端 `ComplianceText` 过滤对 C 端输出继续生效
- 文案层面把"医疗 / 诊断 / 治疗"替换为"健康管理 / 健康记录 / 数据趋势"

## 四、技术选型：uni-app

同为 Vue 生态，`frontend-user` 的 SFC 结构、组合式 API、`shared/` 下纯 TS 模块
（`metric-ranges` / `dict` / `*-labels` / `lifestyle-options`）可原样复用，重写范围集中在视图层与请求层。

| 层 | H5 现状 | 小程序方案 |
|---|---|---|
| 组件库 | Vant 4（26 个组件） | uni-ui + vant-uniapp 按需引入 |
| 路由 | vue-router `createWebHistory` | `pages.json` + `uni.navigateTo`，守卫改为 `addInterceptor` |
| 请求 | `fetch` + `Headers` | `uni.request` |
| 上传 | `FormData` + `fetch` | `uni.uploadFile` |
| 存储 | `localStorage` | `uni.getStorageSync` / `setStorageSync` |
| 图表 | ECharts 5 | uCharts（qiun-data-charts） |
| 打印 | `window.print` | canvas 生成图片 + `uni.saveImageToPhotosAlbum` |
| 推送 | Service Worker + Web Push | 删除，改**微信订阅消息** |
| 实时 | `EventSource` SSE | `uni.connectSocket`（WebSocket） |
| 登录 | 账号密码 | `wx.login` 静默授权 + 手机号快速验证 |
| 样式 | px | rpx + 安全区（底部 tabBar / 刘海屏） |

## 六、后端改造项

现有 `/api/c/v1/**` 业务接口**全部复用，无需改动**。新增：

| 接口 | 说明 |
|---|---|
| `POST /api/c/v1/auth/wechat` | `code` → `code2session` → openid/unionid 绑定 → 换发 token |
| 订阅消息授权记录 | 存 `templateId` + 用户授权状态，用药提醒下发 |
| CareChat WebSocket 端点 | 替代 SSE（`wx` 无 `EventSource`） |

注意：现有 H5 的账号密码登录链路保留，小程序登录为并行的第二条链路，共用同一 token 体系。

## 八、建议的启动顺序

**先内测验证，再谈合规上架**：

1. 注册正式小程序账号（测试号不行），拿到 AppID
2. 开发者工具内开通云开发，建 `healix-proxy` 云函数代理后端 —— 当天就能跑
3. 搭 uni-app 骨架，先迁首页，凭体验版给 2–3 人内测
4. **并行提交 ICP 备案**（最长耗时，别等开发完才启动）
5. 内测稳定后，再按第三节做减法（类目 / 健管师对话 / OCR），切回自有域名提审
