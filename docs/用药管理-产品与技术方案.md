# 用药管理 产品与技术方案

| 项 | 内容 |
|---|---|
| 状态 | **已定稿（grill 两轮），一次性交付，不分期** |
| 依据 | 现有 `people_medication` / `people_medication_intake`、`MedicationFrequencySupport`、`依从性看板-产品与技术方案.md`、`C端激励体系-产品与技术方案.md`、过敏模块 `AllergenCatalog`、工作台任务 `WorkspaceTaskType` |
| 范围 | C 端「用药管理」从**单页记录**升级为**今日服药时间线 + 到点提醒 + 依从回看 + 拍照添加 + 安全反馈**；B 端核对与反馈处理 |
| 不做 | 药品余量 / 续药提醒、家属代管、医保 / 电子处方流转、智能药盒 |

---

## 1. 现状与问题

### 1.1 已有能力

| 层 | 能力 |
|---|---|
| 数据 | 用药清单（药名/用法/频次/剂量/起止/疗程/时机/备注/不良反应标记/来源/状态）；按「药 × 日期 × 时段」打卡（TAKEN / MISSED / SKIPPED） |
| 规则 | `MedicationFrequencySupport`：频次文本 → 每日应服次数与建议时段（QD→OTHER，BID→早晚…），PRN 不计应服 |
| B 端 | 用药表格、处方成组开立、药品目录、单条依从补录、药品 OCR（`MedOcrRecognitionService`，仅 B 端） |
| C 端 | `MedicationsView`：当前/历史 Tab，每药按时段「已服 / 漏服 / 跳过」；可自添加、编辑 |
| 联动 | 首页「今日用药」；激励 `MED` +5/时段；日批 `DAILY_HEALTH_TODO`；`MEDICATION_EXPIRE`；PWA + Web Push 已接通 |

### 1.2 问题

1. 以药为中心，多药客户逐卡找按钮；
2. 无到点提醒；
3. 只记结果不记时刻；
4. C 端只能看今天；
5. 患者可直接改医护开立药的剂量/频次（后端未按来源限制）；添加时不比对药物过敏；无法上报不适；
6. 患者自添加药医护无感；
7. QD 药统一落 OTHER 槽，无法表达「睡前吃」。

---

## 2. 决策

| # | 决策 |
|---|---|
| D1 | **医护开立药（source≠PATIENT）**：药名、剂量、单位、用法、频次、起止、疗程 C 端只读；**时段、提醒、备注、服药时机**患者可改。可「申请调整 / 报告不适 / 我已停药」 |
| D2 | 交付范围：时间线、批量打卡、服药时刻、14 天记录、到点提醒、过敏比对、不适/调整/停药反馈、自添加核对、**拍照识别添加**、**PRN 同日多次**。不做余量与家属代管 |
| D3 | 提醒**默认开启**；每时段到点 1 次 + 跟进 1 次；跟进间隔患者可选 15 / 30 / 60 分钟 / 关闭，默认 30；默认时间 早 08:00、午 12:00、晚 18:00、睡前 21:30 |
| D4 | 补记只允许**今天和昨天**；昨天的记录 `backfill=1`、`taken_at` 可空；激励按现有补记规则 |
| D5 | 药物过敏冲突**只提醒不拦截**，保存后生成健管师任务 |
| D6 | 患者自添加药 B 端标「待核对」，按患者**每日合并 1 条**核对任务；无负责健管师则不建任务 |
| D7 | 用药入口默认「今日服药」时间线；首页卡片只显示**下一个时段**的药 + 「全部已服」；全部完成显示「今日已全部服完」 |
| D8 | QD 药按服药时机推断时段（晨起/早餐前后→MORNING，午餐→NOON，晚餐→EVENING，睡前→BEDTIME，其余→MORNING），可改；**时间线不再出现 OTHER 组**；一次性迁移历史 QD 打卡 OTHER→推断时段 |
| D9 | 当天未打卡的时段**不写行**，统计为「未记录」，与患者主动「漏服」分开展示；依从率 = 已服 ÷ 应服（未记录计入分母） |
| D10 | 「我已停药」立即停用并停止提醒，必填原因（自觉好转 / 副作用 / 医生让停 / 其他）；选「副作用」顺带进入不适上报；生成健管师任务 |
| D11 | 不适上报：症状多选（皮疹或瘙痒、头晕、胃肠不适、心慌、乏力、咳嗽、水肿、其他）+ 轻/中/重 + 选填描述；**重度**页面提示「请尽快就医，严重时拨打 120」且任务**高优先级** |
| D12 | PRN：「记录一次」每次一行带时刻，单药每日上限 6 次；不计依从、不计激励；时间线单独一栏「今日已用 N 次」 |
| D13 | 拍照识别：拍药盒/处方 → 识别列表（≤10 条）逐条可改/删 → 确认后批量保存为 PATIENT 来源（走 D6 核对）；识别结果只预填不直接入库 |
| D14 | 开启服药提醒的患者，`DAILY_HEALTH_TODO` 摘要不再列用药；关闭的照旧 |

默认处理（未单独讨论）：

- 隔日 / 每周服药按 `isDueOnDay` 判断当天是否应服、是否提醒；
- 提醒点开进入 `/medications`；
- 健管师处理反馈的备注回显在患者该药详情「健管师回复」；
- B 端也可修改时段（`slots_json`）。

## 3. C 端设计

### 3.1 信息架构

```
用药管理 /medications
├─ 今日服药（默认 Tab）   时间线：早 / 午 / 晚 / 睡前 + 需要时服用
├─ 我的药箱              在用 / 已停用；添加（手动 / 拍照）、详情
├─ 服药记录              近 14 天趋势 + 每日明细 + 依从率 / 按时率
└─ 提醒设置（右上角）     开关、各时段时间、跟进间隔、推送权限引导
```

### 3.2 今日服药

```
08:00 早上                          [全部已服]
  ○ 缬沙坦胶囊    80mg · 1粒 · 饭后
  ○ 二甲双胍片    0.5g · 1片 · 随餐
  ✓ 阿司匹林肠溶片 100mg · 08:12 已服

12:00 中午   ……
21:30 睡前   ……

需要时服用
  布洛芬缓释胶囊  今日已用 1 次   [记录一次]
```

- 点圆圈 = 已服（`taken_at=now`）；再点弹出操作：改为漏服 / 跳过 / 修改服药时间 / 撤销
- 「全部已服」只写该时段未打卡的药
- 时段已过且未打卡：时间显示橙色「未记录」
- 顶部日期切换：今天 / 昨天（D4），昨天打卡标「补记」

### 3.3 我的药箱

- 卡片：药名规格、用法用量、频次、时段、来源标签（医护开立 / 自己添加·待核对 / 自己添加·已核对）
- 详情页：
  - 医护开立药：医疗字段只读；可改时段与备注；底部「申请调整」「报告不适」「我已停药」
  - 自添加药：全部可编辑、可删除；「报告不适」「我已停药」
  - 不适/反馈历史与健管师回复
- 添加：药品目录搜索（开放 C 端只读）或手输；**拍照添加**入口
- 保存前调用过敏预检，命中弹窗「档案记录你对【青霉素类】过敏，阿莫西林属于该类。已同时通知健管师，建议先咨询后再服用」→ 仍可保存

### 3.4 服药记录

- `DailyTrendChart` 近 14 天：值 = 当日已服时段 ÷ 应服时段；全部完成 `on`，部分 `soft`，有漏服/未记录 `warn`
- 统计卡：依从率、按时率（`taken_at` 与提醒时间差 ≤ 60 分钟）、漏服次数
- 明细：按天展开，每时段每药状态（已服 08:12 / 漏服 / 跳过 / 未记录 / 补记）

### 3.5 提醒设置

- 总开关、4 个时段时间（时间选择器）、跟进间隔（15 / 30 / 60 / 关闭）
- 推送状态：未授权 → 「开启通知」；iOS 非主屏模式 → 引导「添加到主屏幕」；均失败时提示仅站内信

### 3.6 首页卡片

- 取下一个「有未打卡药」的时段：「21:30 睡前 · 2 种药」+ 药名 +「全部已服」
- 全部完成：「今日已全部服完 ✓」；当天无应服药：卡片隐藏（仅有 PRN 药也隐藏）

## 5. 数据模型

### 5.1 改表

```sql
ALTER TABLE people_medication
    ADD COLUMN drug_code            VARCHAR(64)  NULL COMMENT '药品目录编码' AFTER drug_name,
    ADD COLUMN slots_json           VARCHAR(128) NULL COMMENT '服药时段覆盖 ["MORNING","BEDTIME"]；空=按频次+时机推导',
    ADD COLUMN verified_at          DATETIME     NULL COMMENT '自添加药医护核对时间',
    ADD COLUMN verified_by_staff_id VARCHAR(32)  NULL,
    ADD COLUMN allergy_conflict     VARCHAR(255) NULL COMMENT '命中的药物过敏摘要；空=无',
    ADD COLUMN stop_reason          VARCHAR(32)  NULL COMMENT '患者自述停药原因 IMPROVED/SIDE_EFFECT/DOCTOR/OTHER';

ALTER TABLE people_medication_intake
    ADD COLUMN dose_seq  TINYINT  NOT NULL DEFAULT 1 COMMENT 'PRN 同日第几次；定时药恒为 1' AFTER time_slot,
    ADD COLUMN taken_at  DATETIME NULL COMMENT '实际服药时刻',
    ADD COLUMN backfill  TINYINT  NOT NULL DEFAULT 0 COMMENT '1=次日补记',
    DROP INDEX uk_med_intake_day_slot,
    ADD UNIQUE KEY uk_med_intake_day_slot (medication_id, intake_date, time_slot, dose_seq, gmt_deleted);
```

- 时段枚举新增 `PRN`（需要时服用）；OTHER 仅保留兼容历史，新数据不再写入
- `SchemaEnsureRunner` 负责老库补列与唯一键重建

### 5.2 新表

```sql
CREATE TABLE IF NOT EXISTS people_medication_reminder (
    -- pk_id / id / tenant_id / people_id + 通用审计列
    enabled        TINYINT  NOT NULL DEFAULT 1,
    morning_at     CHAR(5)  NOT NULL DEFAULT '08:00',
    noon_at        CHAR(5)  NOT NULL DEFAULT '12:00',
    evening_at     CHAR(5)  NOT NULL DEFAULT '18:00',
    bedtime_at     CHAR(5)  NOT NULL DEFAULT '21:30',
    follow_up_min  INT      NOT NULL DEFAULT 30 COMMENT '0=不跟进',
    UNIQUE KEY uk_med_reminder_people (tenant_id, people_id, gmt_deleted)
) COMMENT='服药提醒设置；无行=默认开启+默认时间';

CREATE TABLE IF NOT EXISTS people_medication_reminder_log (
    pk_id, tenant_id, people_id,
    remind_date  DATE        NOT NULL,
    time_slot    VARCHAR(16) NOT NULL,
    seq          TINYINT     NOT NULL COMMENT '1=到点 2=跟进',
    sent_at      DATETIME    NOT NULL,
    UNIQUE KEY uk_med_remind (people_id, remind_date, time_slot, seq)
) COMMENT='服药提醒发送去重';

CREATE TABLE IF NOT EXISTS people_medication_feedback (
    -- pk_id / id / tenant_id / people_id + 通用审计列
    medication_id   VARCHAR(32)  NOT NULL,
    kind            VARCHAR(16)  NOT NULL COMMENT 'ADVERSE / ADJUST / STOPPED / ALLERGY_CONFLICT',
    symptoms_json   VARCHAR(255) NULL,
    severity        VARCHAR(16)  NULL COMMENT 'MILD / MODERATE / SEVERE',
    content         VARCHAR(500) NULL,
    status          VARCHAR(16)  NOT NULL DEFAULT 'OPEN' COMMENT 'OPEN / HANDLED',
    work_task_id    VARCHAR(32)  NULL,
    handled_by_staff_id VARCHAR(32) NULL,
    handled_at      DATETIME     NULL,
    reply           VARCHAR(500) NULL,
    KEY idx_med_feedback_people (tenant_id, people_id, status)
) COMMENT='患者用药反馈';
```

### 5.3 迁移

一次性（`SchemaEnsureRunner` 幂等）：对 `dosesPerDay=1` 且非 PRN 的药，按 D8 推断时段，把其 `time_slot='OTHER'` 的打卡改为推断槽（同日目标槽已存在则跳过）。PRN 药历史 OTHER 打卡改为 `PRN`。

### 6.4 提醒扫描

- `JobCatalog.MEDICATION_REMIND`，每 5 分钟；`NotifyEventType.MEDICATION_REMIND(ADHERENCE)`，路由站内信 + Web Push
- 候选人：C 端已激活、提醒开启（或无设置行）、当天存在应服非 PRN 在用药
- 对每个时段：`now ≥ 提醒时间` 且该时段有未打卡药 → seq=1；`now ≥ 提醒时间 + follow_up_min` 且仍未打卡 → seq=2；写 `reminder_log` 唯一键去重后发送
- 超过提醒时间 2 小时不再补发（服务重启 / 积压场景）
- 文案：「08:00 该吃药了：缬沙坦、二甲双胍等 3 种」/「早上的药还没记录，吃了记得点一下」
- `NotifyReminderScanService`：提醒开启的人摘要中去掉用药（D14）

### 6.5 激励与统计口径

| 项 | 口径 |
|---|---|
| 激励 | 不变：定时药每时段 TAKEN +5；批量逐条；医护代录、PRN 不计；昨天补记按现有补记规则 |
| 依从率 | 已服 ÷ 应服（应服 = 当天 due 药 × 时段数，不含 PRN）；SKIPPED 计入分母不计分子 |
| 按时率 | TAKEN 且 `taken_at` 与该时段提醒时间差 ≤ 60 分钟 ÷ TAKEN 数（补记不计入） |
| 依从性看板 | 用药完成率改用 `MedicationScheduleService` |
| 管理报告 / 周报 | 用药小节增加依从率、按时率、不适上报次数 |
| 健管助手 | `PatientBizTools` / `StaffBizTools` 增加「近 14 天用药依从」只读工具 |

### 6.6 工作台任务

| 类型 | 触发 | 优先级 | 时限 |
|---|---|---|---|
| `MED_FEEDBACK` 用药反馈 | 不适上报、申请调整、患者停药、过敏冲突 | 重度不适 / 过敏冲突 HIGH，其余 MEDIUM | HIGH 1 天，其余 3 天 |
| `MED_VERIFY` 用药核对 | 患者自添加药（按人每日合并，已有未关闭任务则追加） | LOW | 3 天 |

- 指派：负责健管师；无负责人不建（反馈仍落库，B 端可见）
- 关闭：`MED_FEEDBACK` 处理反馈即关闭；`MED_VERIFY` 该患者待核对药全部核对后自动关闭

| B | 工作台任务类型文案与表单 | `MED_FEEDBACK` / `MED_VERIFY` |

## 8. 验收要点

1. 三种药（QD 晨起、BID、QN 睡前）→ 时间线 早（2）/ 晚（1）/ 睡前（1）；「全部已服」写 TAKEN 且 `taken_at` 一致
2. 医护开立药：C 端改剂量被忽略或拒绝；改时段生效；删除返回 403
3. 08:00 提醒：08:00–08:05 收到 1 条；08:30 仍未打 → 第 2 条；已打卡不发第 2 条；跟进设为关闭则只 1 条
4. 昨天可补记（标补记），前天不可
5. 档案青霉素类过敏，添加阿莫西林 → 弹窗；保存成功；健管师出现 HIGH `MED_FEEDBACK`
6. 不适上报「重」→ 页面就医提示；任务 HIGH；该药标不良反应；健管师回复后患者详情可见
7. 停药选「副作用」→ 药停用、提醒停止、进入不适上报
8. PRN 记录 6 次后第 7 次被拒；不计激励与依从
9. 历史 QD 药 OTHER 打卡迁移后在对应时段显示已服；重复执行迁移无副作用
10. 拍药盒识别 3 条 → 删 1 改 1 → 保存 2 条 PATIENT 来源 → 健管师当日 1 条 `MED_VERIFY`
11. 当天未打卡时段在记录页显示「未记录」，与「漏服」区分；依从率计入分母

## 9. 风险

| 风险 | 应对 |
|---|---|
| iOS Web Push 需添加到主屏 | 设置页检测引导；站内信兜底 |
| 时机文本推断时段不准 | 推断结果可见可改；`slots_json` 优先 |
| 收紧医护药编辑后的历史改动 | 不回滚；修订历史可追溯 |
| 改唯一键 | `SchemaEnsureRunner` 先建新键再删旧键，幂等 |
| 扫描量增长 | 仅扫有应服药且开启提醒者；后续可加 `next_remind_at` |
| 过敏误报 / 漏报 | 只提醒不拦截；按类别优先、别名兜底；健管师复核 |
| OCR 识别错误 | 只预填，逐条确认；保存后仍走核对 |
