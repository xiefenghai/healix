| 项 | 内容 |
|---|---|
| 版本 | **v0.4** |
| 日期 | 2026-09-08 |

| 表名 | **`followup_record`** |

---

## 1. 两层类型命名

| 层 | 枚举 / 字段 | 含义 |
|----|-------------|------|
| **记录通道** | `FollowupRecordType` / `record_type` | `PERIODIC` / `METRIC_REVIEW` / `PLAN_NUDGE` |
| **随访类型** | `FollowupType` / `followupType` | 用户可建：常规回访、入组首诊等 |

禁止使用 `purpose` / `FollowupKind` 等别名。

---

## 2. `FollowupType`（用户可建）

| followupType | 文案 |
|--------------|------|
| `ROUTINE` | 常规健康回访 |
| `PLAN_ADHERENCE` | 方案执行随访 |
| `MEDICATION` | 用药随访 |
| `SYMPTOM_METRIC` | 指标/症状随访 |
| `ONBOARDING` | 入组/首诊随访 |
| `OTHER` | 其他随访 |

写入 `content_json.followupType`。

---

## 3. 按类型差异化表单

共用外壳：`contactTarget` / `followupMethod` / `guidance`（选填）。

专属字段写入 `content.section`：

### `ONBOARDING` 入组/首诊

表单内嵌患者档案编辑（基础档案含生活习惯 + 病种档案），提交时先 `PUT` 写回档案，再办结随访。

| 字段 | 必填 |
|------|------|
| 档案表单（basic + disease） | 提交时写回 |
| `section.nextAction` | 是 |
| `section.archiveWritten` | 是（前端写回后置 true） |
| `section.diseaseCodes[]` | 否（本次写回的病种） |

### `ROUTINE` 常规健康回访

| 字段 | 必填 |
|------|------|
| `adherenceNote` | 是 |
| `lifestyleLevel` | 是 GOOD/FAIR/POOR |
| `lifestyleNote` | 否 |
| `planSatisfaction` | 是 |
| `unsatisfiedReason` | 不满意时必填 |
| `symptomNote` | 否 |
| `suggestPlanAdjust` | 否（顶层）；为 true 时办结后确保工作台有 OPEN 的 `PLAN_CREATE`（摘要「随访建议调整方案」），发布方案后按现有逻辑关单 |

### 其余类型（暂）

`section.content` 通用文本。

## 4. API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/b/v1/followups` | `followupType` + `content.section` |
| POST | `/api/b/v1/followups/{id}/complete` | 同上 |
| GET | `/api/b/v1/followups` | 返回 `followupType` / `followupTypeLabel` |
