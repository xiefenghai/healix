# 智能体会话可点击气泡 — 前后端技术方案

| 项 | 内容 |
|---|---|
| 版本 | **v1.0** |
| 日期 | 2026-11-10 |
| 状态 | **已落地**（驾驶舱 `CockpitView` + `health-agent`） |
| 范围 | B 端健管智能体：会话回复附带可点击动作芯片（气泡按钮） |
| 核心文件 | 后端 `AgentAction` / `AgentResponse` / `StaffAgentGateway`；前端 `CockpitView.vue` |

---

## 1. 产品目标

智能体回复不只是文字，还会在气泡下方挂出**可点击动作**（Action Chip），让健管师一键：

- 打开抽屉 / 弹窗（建档、建组、首诊、方案、报告…）
- 切换左侧患者焦点
- 触发下一轮带 `capabilityHint` 的会话（生成方案、建档…）
- 确认后调用现有 B 端 API（提醒、发报告、办结任务…）

原则：**文案承诺的按钮必须真实可点**；写库类操作必须人点确认，禁止静默落库。

---

## 2. 端到端链路

```
用户发消息
    │
    ▼
前端 POST /api/b/v1/agent/chat/stream  (SSE)
    │
    ▼
BAgentController → StaffAgentGateway.streamChat
    │
    ▼
StaffReActRunner（选工具 / Handler）
    │  产出 AgentResponse { reply, actions[], capability, intent, … }
    ▼
SSE event: result(AgentResponse) → done
    │
    ▼
前端把 data.actions 挂到本轮 assistant 气泡
    │
    ▼
渲染 action-chip → 点击 runAction(action) → 分发到抽屉 / API / 再发消息
```

会话落库时，助手消息会一并持久化 `actions`（`conversationService.appendAssistant(sessionId, reply, actions)`），刷新/恢复会话后按钮仍可点。

## 3. 后端：动作协议

### 3.1 数据结构

`AgentAction`（`com.healix.agent.gateway.AgentAction`）：

| 字段 | 含义 |
|---|---|
| `type` | 动作类型（见下表） |
| `label` | 按钮文案（用户可见） |
| `path` | 随 `type` 变化：路由 / 抽屉 mode / API 键 / 能力码 |
| `peopleId` | 可选；绑定患者后前端可先切焦点再执行 |
| `payload` | 可选扩展（预填、禁用态、草稿内容等） |

`AgentResponse`：

```text
sessionId | capability | intent | reply | actions[] | safetyFlags | extracted
```

流式结束时通过 `AgentStreamEvent.result(AgentResponse)` 下发；前端只在 `result` 事件里取 `actions`。

### 3.2 动作类型一览

| type | path 含义 | 典型场景 | 前端行为 |
|---|---|---|---|
| `NAVIGATE` | 驾驶舱内路径键或路由 | `create-archive` / `create-care-team` / `join-care-team` / `ocr-upload` / `unassigned-workbench` | 打开对应弹窗/面板；未知 path 则 `router.push` |
| `OPEN_SHEET` | 右侧抽屉 mode | `intake` / `care-plan` / `reports` / `followups` / `archive` / `observations` / `care-chat` | `openSheet` / `openIntakeSheet` |
| `FOCUS_PATIENT` | — | 切入某患者 | `selectPatient`；`payload.autoAsk=false` 时不追问 |
| `TRIGGER_CAPABILITY` | 能力码 | `CREATE_ARCHIVE` / `CARE_PLAN` / `REPORT_SUMMARY` / `GENERAL_CHAT` | 自动 `sendMessage(…, capabilityHint)` |
| `CALL_API` | API 键 | `NUDGE` / `CREATE_FOLLOWUP` / `PUBLISH_REPORT` / `PUBLISH_CARE_PLAN` / `CREATE_ARCHIVE` / `COMPLETE_TASK` … | `executeCallApi`；`runState`: busy → done |
| `SET_COCKPIT_TAB` | `urgent` / `watch` / `mine` | 切左栏 Tab | 改 `tab`；部分文案顺带开批量台 |
| `REFRESH` | — | 刷新简报 | `refreshBriefing` |

工厂方法集中在 `AgentAction`：如 `createCareTeam`、`openCreateArchive`、`focusPatient`、`openSheet`、`callApi`、`triggerCapability` 等，避免各 Handler 手写不一致的 JSON。

### 3.3 动作从哪里来

1. **业务工具直接产出**  
   `StaffBizTools` 按患者状态 / 待办拼装动作列表（补档案、提醒打卡、生成方案、办结任务等）。

2. **能力 Handler 产出**  
   例如 `CreateArchiveHandler`：缺信息时挂 `NAVIGATE create-archive`（预填 draft）；确认入库挂 `CALL_API CREATE_ARCHIVE`。

3. **GeneralChat 兜底对齐**（机构会话尤其关键）  
   `GeneralChatHandler` 在模型回复后做「文案 ↔ 按钮」一致性修补：
   - 未建组：强制挂建组入口 + 置灰的批量分配面板
   - 明确建组意图：确保 `create-care-team`，必要时改写 reply 为「已打开创建面板…」
   - 回复提到批量面板：去掉抢焦点的姓名 chip，只留面板按钮
   - `dedupeActions` 去重；`alignReplyWithVisibleActions` 避免「点下方某某」却无按钮

4. **前端本地合成**（非 SSE）  
   今日简报、新手起步、建组成功回执等，也可在 `CockpitView` 内直接 `messages.push({ actions })`，协议与后端一致。

### 3.4 网关与持久化

`StaffAgentGateway.doChat`：

1. ReAct 跑完得到 `AgentResponse`
2. 机构会话限制：除闲聊 / 建档外，其它能力被拦截成提示文案（无 actions）
3. `appendAssistant(sessionId, reply, actions)` 落库
4. SSE：`result`（含 actions）→ `done`

## 4. 前端：渲染与点击

主实现：`frontend-admin/src/portals/workspace/CockpitView.vue`。

### 4.1 类型与消息模型

```ts
interface AgentAction {
  type: string
  label: string
  path?: string
  peopleId?: string
  payload?: Record<string, unknown>
  runState?: 'busy' | 'done'  // 仅前端执行态
}

interface ChatMessage {
  role: 'user' | 'assistant' | 'system'
  content: string
  actions?: AgentAction[]
  // …
}
```

SSE `result` 到达后：`row.actions = data.actions`（方案能力会微调文案 / 补预览按钮）。

### 4.2 展示管线

```
msg.actions
  → visibleActions      // 弹窗已开时隐藏竞争入口（建档/建组）
  → bubbleActions       // 去重单例 CTA；未建组时建组按钮排前
  → shownActions        // 默认预览前 3 个，其余「展开」
  → action-chip UI
```

视觉约定：

| 状态 | 表现 |
|---|---|
| 主按钮 | `.primary`（未建组时强制建组；或首个 / CALL_API / TRIGGER） |
| 锁定 | `.locked` + Tooltip（如未建组时的批量面板，`payload.disabled`） |
| 已完成 | `.done` / `runState=done`（不可再点；建组成功可改文案为「✅ 已成功创建」） |
| 请求中 | `runState=busy` → 「处理中…」 |

简报区 `briefingUiActions` 与对话气泡共用同一套 chip 组件与 `runAction`。

### 4.3 点击分发 `runAction`

统一入口，按 `type` / `path` 分支：

| 分支 | 行为摘要 |
|---|---|
| 未建组 + 需组能力 | `ElMessage.warning`，引导左侧第一步 |
| `FOCUS_PATIENT` | 切患者；支持 `batchServe` 开批量服务台 |
| `NAVIGATE create-care-team` | 打开建组弹窗，可读 `payload.name` 预填 |
| `NAVIGATE create-archive` | 打开建档弹窗，可读 draft 预填 |
| `NAVIGATE join-care-team` | 打开分配健管组对话框 |
| `NAVIGATE ocr-upload` | 切患者后打开单据上传 |
| `NAVIGATE unassigned-workbench` | 打开未分组批量台 |
| `OPEN_SHEET` | 打开右侧 Sheet / 首诊 |
| `TRIGGER_CAPABILITY` | 再发一轮带 hint 的消息 |
| `CALL_API` | `executeCallApi`，成功标 `done` |
| `SET_COCKPIT_TAB` | 切左栏 |
| `REFRESH` | 刷简报 |

部分路径会在打开前自动 `selectPatient`，保证动作落在正确患者上下文。

### 4.4 与弹窗的协同

- 建档弹窗打开时：`visibleActions` 隐藏同义的建档 chip，避免左/中/右三处抢焦点。
- 明确「建组」短口令：前端 `asksCreateCareTeamIntent` 可**短路**直接开建组弹窗，不必等 SSE（与后端意图对齐）。
- 建档缺信息：`CREATE_ARCHIVE` + `CREATE_ARCHIVE_NEED_INFO` 时，前端自动开抽屉并保留后端话术。

## 5. 关键场景对照

| 用户说法 / 能力 | 后端挂的动作 | 点击后 |
|---|---|---|
| 「建组」「创建健管组」 | `NAVIGATE create-care-team`（可带 name） | 打开建组弹窗 |
| 「帮我建档」/ 粘贴建档稿 | `NAVIGATE create-archive` + draft | 打开建档弹窗并预填 |
| 未建组时的机构闲聊 | 建组主按钮 + 置灰批量面板 | 先建组；面板提示不可点 |
| 点名某患者 | `FOCUS_PATIENT` | 切入左栏该患者 |
| 「生成方案」 | `TRIGGER_CAPABILITY CARE_PLAN` | 再发消息带 hint，走方案流 |
| 「提醒患者」 | `CALL_API NUDGE` | 调提醒 API，按钮变 done |
| 简报「立即处理」 | `SET_COCKPIT_TAB` / `OPEN_SHEET` 等 | 切 Tab 或开抽屉 |

## 6. 设计约束（实现时务必遵守）

1. **有文案就有按钮**：回复写了「点下方××」，`actions` 必须含对应可点项；否则改文案或补动作（见 `GeneralChatHandler`）。
2. **人确认才写库**：`CALL_API` / 建档确认等不得在模型侧静默执行。
3. **禁用要说清原因**：`payload.disabled` + `disabledReason`，前端 Tooltip / Message。
4. **单例入口**：建组 / 建档 / 批量面板等全会话只保留最新气泡上的同类 CTA，避免历史气泡堆一排蓝按钮。
5. **机构会话边界**：无患者时只允许闲聊与建档类能力；其它能力网关层拦截。
6. **Teleport / 挂载**：局部弹窗（如建档挂中间栏）须等挂载点进 DOM 再 `append-to`，避免首帧 Teleport 告警。

## 8. 扩展指南（加一种新按钮）

1. 后端：在 `AgentAction` 增加工厂方法（或复用现有 type + 新 path）。
2. Handler / Tools：把动作放进 `AgentResponse.actions`。
3. 若文案会提到该按钮：在 `GeneralChatHandler`（或对应 Handler）做「提到则 ensure」对齐。
4. 前端：在 `runAction` 增加分支；必要时更新 `visibleActions` / 主次按钮 / 锁定规则。
5. 补单测：意图匹配、动作去重、点击后状态（done / locked）。

---

## 9. 一句话总结

**后端用结构化 `AgentAction[]` 描述「下一步可点什么」，经 SSE `result` 下发并落库；前端挂在助手气泡上按 type 分发到弹窗、抽屉、再对话或 B API。** 文案与按钮由 Handler 兜底对齐，保证「看得见、点得着、点完有结果」。
