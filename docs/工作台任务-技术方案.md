## 1. 产品目标

### 1.1 一句话

让健管师打开工作台就能处理 **必须推进的事项**：未入组、未出方案、连续未打卡、居家指标异常；每笔催办/审阅都留得住痕迹。

### 1.2 与依从性看板的分工

| | 依从性看板 | 工作台任务 |
|--|------------|------------|
| 问题 | 今天谁红了、趋势如何 | 哪几件事现在必须有人做完 |
| 数据 | 在线聚合，不落工单 | 落库待办，可领取/关单/审计 |
| 红了之后 | 人肉翻详情 | 深链 + 表单关单 |

看板保留；**不把看板当待办。**

### 1.3 成功标准（P0）

1. 侧栏「工作台」能切 **公共池 / 我的待办 / 今日已办**；管理员另有 **全部** 视图   
2. 四类任务能自动开、按规则进池、条件满足或表单提交后能关  
3. 未领取不能填督促/审阅单；领取/退回/分派/关单进 `audit_log`  
4. 入组/出方案/督促/异常：同一患者同一类型同时最多一条 OPEN；异常新测量并入 OPEN 单的 `hits`

## 2. 业务路径与任务类型

```text
本机构 ACTIVE 患者、扫描时仍无健管组
    → TEAM_ASSIGN 分配健管组        【公共池】【可领】【绑定组后自闭】

已入组、扫描时仍无 ACTIVE 方案
    → PLAN_CREATE 制定方案          【个人池=主责健管师】【可领】【发布后自闭】

方案连续未执行 ≥ 3 天（本轮未催过）
    → PLAN_NUDGE 打卡跟进           【个人池】【须领后填回执】

异常测量（血压/血糖/心率/BMI）写入且 H/L
    → 无 OPEN：开一张 METRIC_ALERT（指标异常）；有 OPEN：并入 hits
    → 【个人池】【须领后填审阅】【一次审阅关全部 hits；恢复正常也不关】
```

P1/P2 类型：`FOLLOW_UP`（定期随访，见 `随访-产品与技术方案.md`）、`REPORT_REVIEW`（周报/月报审阅，P2）。

**改方案**：随访勾选「建议调整方案」时创建或复用 OPEN 的 `PLAN_CREATE`（不另开类型）；发布方案后关单。

## 3. 信息架构

### 3.1 导航

```text
机构工作台侧栏
  ├─ 工作台            ← 新增，默认落地
  ├─ 患者管理
  ├─ 依从性看板
  ├─ 健管组
  └─ 成员管理
```

路由：`/workspace/tasks`  
任务行深链患者页对应 Tab（健管组/方案/指标）。

### 3.2 页面结构

```text
┌ 工作台    [公共池] [我的待办] [今日已办]  （管理员+ [全部]）  类型▾  状态▾  健管组▾ ┐
├ 摘要：公共池 N · 我的待办 M · 今日已办 K（点卡切池，与列表同口径）              │
├ 患者 | 类型 | 摘要 | 处理人 | 到期 | 开单/完成时间 | 操作                         │
│ （「全部」视图额外展示：状态、归属）                                            │
└─────────────────────────────────────────────────────────────────────────────┘
```

- **公共池**：`assignee_staff_id IS NULL` 且 `status=OPEN`  
- **我的待办**：`assignee_staff_id = 当前员工` 且 `status=OPEN`  
- **今日已办**：本人今日 `status=DONE`（见 API）  
- **全部**：本机构任务（含已完成/已取消/已过期），仅 `TENANT_ADMIN`；运营审计用，**不是第三池**

列表列说明：

| 列 | 何时展示 | 含义 |
|----|----------|------|
| 状态 | 仅「全部」 | 任务生命周期：`OPEN`→**待处理**，`DONE`→**已完成**，`CANCELLED`→已取消，`EXPIRED`→已过期 |
| 归属 | 仅「全部」 | **公共** / **个人**（无归属人=公共，有归属人=个人） |
| 归属人 | 公共池 / 我的待办 / 全部 | 当前领取人 `assignee`（未领为 `-`） |
| 处理人 | 今日已办 / 全部（已关闭行） | 实际关单人 `done_by`（条件自闭如管理员发方案，显示操作者） |

公共池 / 我的待办 / 今日已办 顶部 Tab 已表达归属与办结范围，故不重复展示「状态」「归属」。

医生、健管师默认只看公共池 + 自己的个人池，**不能看见他人个人池**。  
医生公共池列表 **过滤掉** `TEAM_ASSIGN` / `PLAN_CREATE`；这两类若被管理员分派到医生，只出现在该医生「我的待办」。

## 4. 池模型与分派

待办一张表，用处理人空/非空区分池。

| `assignee_staff_id` | 池 |
|---------------------|----|
| `NULL` | 机构公共池 |
| 某 `staff_profile.id` | 该人个人任务池 |

### 4.1 开单时进哪个池

| 类型 | 规则 |
|------|------|
| `TEAM_ASSIGN` | 永远公共池 |
| 其余 | 有 `people_care_assignment.primary_care_manager_staff_id` → 个人池；否则公共池 |

主责医生 **不默认成为处理人**。

### 4.2 池内动作

| 动作 | 谁 | 结果 |
|------|----|------|
| 领取 | 见下表 | 公共池 → 自己；乐观锁 |
| 分派 | `TENANT_ADMIN`，或当前处理人 | 指定员工个人池（医生也可被分派入组/出方案） |
| 退回公共池 | 当前处理人；`TENANT_ADMIN` 可对任意 OPEN | `assignee=NULL`，**必填原因** |
| 填单关单 | **仅当前处理人** | 督促/异常见 §6；未领取禁止填单 |
| 条件自闭 | 系统 | 入组成功 / 方案发布，**不依赖是否已领取** |

**领取资格**

| 类型 | `CARE_MANAGER` / `TENANT_ADMIN` | `DOCTOR` |
|------|--------------------------------|----------|
| `TEAM_ASSIGN` `PLAN_CREATE` | 可领 | 公共池不可领；仅被分派后在个人池处理 |
| `PLAN_NUDGE` `METRIC_ALERT` | 可领 | 可领 |

两人同时领取：`UPDATE … WHERE id=? AND assignee_staff_id IS NULL`，影响行数 0 → 提示「已被领取」。

入组/出方案领取只表示「我在办」，**不是关卡**：别人在健管组页绑组、在方案页发布，任务仍自闭。

### 4.3 入组后的联动

患者加入健管组并写入主责健管师后：

1. 该患者本机构 `TEAM_ASSIGN` OPEN → `DONE`（`close_reason=CONDITION`）  
2. 该患者其余 OPEN 且仍在公共池的任务 → 改派到主责健管师  

主责健管师更换：该组患者名下 OPEN 且处理人是旧主责的任务 → 改派新主责（已领取的督促单若正在填，以保存时处理人校验为准）。

## 5. 开单 / 更新 / 关单规则

### 5.1 去重

应用层：`findOpen(tenantId, orgId, taskType, bizKey)`。  
库表用生成列保证同时仅一条 OPEN（见 §8.1 `open_dedup_key`）。

| 类型 | `biz_key` | OPEN 时再扫到 |
|------|-----------|----------------|
| `TEAM_ASSIGN` | `{peopleId}` | 忽略（已有则不新建） |
| `PLAN_CREATE` | `{peopleId}` | 忽略 |
| `PLAN_NUDGE` | `{peopleId}` | 更新连续天数等；**当日应打已完成**（或扫描时 streak&lt;3）→ `CONDITION` 自闭 |
| `METRIC_ALERT` | `{peopleId}` | **并入** `payload.hits`；不另开单 |

`family`：`BP` | `GLUCOSE` | `HR` | `BMI`（写入每条 hit）。  
`sourceRecordId`：血糖/心率 = `vital_record.id`；血压 = `groupId`（成对）否则收缩压记录 id；BMI = 体重记录 id。

同一患者同时最多 **一张** OPEN `METRIC_ALERT`。同一 `sourceRecordId` 不重复计入 hits（含已关单历史）。

关单后再开见 §5.6 / §5.7。

### 5.2 触发

日历日均为 `Asia/Shanghai`。Job 默认 `0 15 0 * * *`。

| 类型 | 事件（即时） | 日批 Job |
|------|----------------|----------|
| `TEAM_ASSIGN` | **不开单**（入组成功时自闭已有 OPEN） | 本机构 ACTIVE 且 **尚未入组** → 开单 |
| `PLAN_CREATE` | 发布时自闭；关单前写入 `payload.carePlanVersionId`（及 `carePlanId`）；今日已办「详情」弹窗打开该版方案预览 | 已入组且 **无 ACTIVE 方案** → 开单 |
| `PLAN_NUDGE` | 可不做实时 | `streakDays >= 3` 且本轮尚未「已接通」催过 |
| `METRIC_ALERT` | 写入后该条测量 H/L → 无 OPEN 则开单，有 OPEN 则并入 hits | 补漏同样并入 / 新开 |

Job：`WORKSPACE_TASK_SCAN`，平台级，默认 Cron `0 15 0 * * *`（0:15，错开用药过期 0:05）。仅 `tenant.status=ACTIVE`。params：`{ "batchSize": 200 }`。

### 5.3 开单 universes

- 本机构 `people_org_membership.status=ACTIVE`  
- 未入组：无本机构 `care_team_member` 且 `member_type=PATIENT`  
- `TEAM_ASSIGN`：本机构 ACTIVE membership，且无本机构 `care_team_member`（`member_type=PATIENT`）  
- `PLAN_CREATE`：已入组，无 ACTIVE `care_plan`  
- 督促：须有执行中方案（与看板 `hasActivePlan` 一致）；连续天数用 `AdherenceQueryService` / `CarePlanDueSupport` 同一套  

### 5.4 异常判定（后端必须有，不能只靠前端）

对齐 B 端 `metric-ranges.ts` / 字典 `metricType` content，缺省成人默认：

| 族 | 规则 |
|----|------|
| `BP` | **时间最近** 的一组收缩+舒张（同 `groupId` 或最接近的一对）；情境 `HOME`/`CLINIC` 均可；任一 H/L 即开 |
| `GLUCOSE` | 时间最近的指尖血糖（按该条餐次范围） |
| `HR` | 时间最近的心率 |
| `BMI` | 时间最近的体重 + 当时最近身高（同组优先），18.5～23.9 外为异常 |

**不出单**：腰围、单次体重、身高、步数、睡眠、体温。

开单 / 并入时 payload 为 **hits 数组**（每条异常测量一条快照）：

```json
{
  "hitCount": 2,
  "hits": [
    {
      "family": "BP",
      "sourceRecordId": "grp_xxx",
      "sys": 156, "dia": 92, "unit": "mmHg",
      "bpContext": "HOME",
      "flags": { "sys": "H", "dia": "H" },
      "recordedAt": "2026-09-07T08:12:00",
      "ref": { "sys": "90~139", "dia": "60~89" },
      "summary": "血压 156/92 mmHg（家庭） 收缩压偏高、舒张压偏高"
    },
    {
      "family": "HR",
      "sourceRecordId": "vr_yyy",
      "value": 180,
      "unit": "bpm",
      "flags": { "hr": "H" },
      "recordedAt": "2026-09-07T16:56:00",
      "summary": "心率 180 bpm 偏高"
    }
  ]
}
```

后续再上传异常 → **并入同一 OPEN 单的 hits**。该条测量之后患者又录了正常值：**本单仍 OPEN**，审阅仍看 hits 快照。一次审阅关单覆盖全部 hits。

### 5.5 关单

| 类型 | 方式 | `close_reason` |
|------|------|----------------|
| `TEAM_ASSIGN` | 已进入本机构健管组 | `CONDITION` |
| `PLAN_CREATE` | 该患者已有 ACTIVE 方案 | `CONDITION` |
| `PLAN_NUDGE` | 当前处理人提交 `PLAN_NUDGE` 回执；**或**患者补打卡使某日应打已完成（实时）/ Job 扫描 streak&lt;3 | `FORM` / `CONDITION` |
| `METRIC_ALERT` | 当前处理人提交 `METRIC_REVIEW` 处理单（覆盖本单全部 hits） | `FORM` |

- 患者补打卡：当该日方案应打任务均已 `DONE`/`SKIPPED`（`due>0` 且无 pending）时，OPEN `PLAN_NUDGE` → `DONE`（`close_reason=CONDITION`），摘要追加「患者已补打卡，条件关闭」；`payload.autoClose=PATIENT_CHECKIN`。日批扫描若仍有 OPEN 且 `streakDays<3` 同样 `CONDITION` 兜底（`STREAK_RECOVERED`）。  
- 指标恢复正常 **不**自动关异常单（须审阅 hits 快照）。  
- 患者退组 / membership 非 ACTIVE：OPEN 任务 `EXPIRED`（`close_reason=EXPIRED`），不要求填单。  
- 管理员 **不能**无单直接 DONE 督促/异常；可 `CANCELLED`（须原因，仅 `TENANT_ADMIN`）。  
- `TEAM_ASSIGN` / `PLAN_CREATE`：**领取可选**；条件满足即自闭。

### 5.6 督促关单后再开（本轮只催一次）

无 OPEN 的 `PLAN_NUDGE` 且 `streakDays >= 3` 时：

| 最近一条已关督促 | 行为 |
|------------------|------|
| 无 | 开单 |
| 回执 `UNREACHED` | 开单（次日扫描即可） |
| 回执 `REACHED` | **仅当本轮连续已被打断** 后再次连续 ≥ 3 才开。打断 = 关单日之后存在一天：方案应打且当日已完成（`done+skipped ≥ due` 且 `due>0`） |
| 管理员 `CANCELLED` | 本轮不再开（与已接通同样等连续打断后再说） |

「本轮」与看板 streak 一致：从今天往回数未完成日，中间 `due=0` 的日历日跳过不算打断。

### 5.7 异常：并入、再开

维度：`peopleId`（整患者一张 OPEN）。

1. 同一 `sourceRecordId` **永远只消费一次**（出现在任一任务 `hits` / 旧版 `biz_key` 即视为已处理）。  
2. 无 OPEN → 新开一张，`biz_key={peopleId}`，`hits=[本条]`。  
3. 有 OPEN → **并入** `hits`，更新摘要（如「心率 180 偏高 等共 2 项异常」）；不另开单。  
4. 审阅 `FORM` 关单后，再有**尚未消费**的新异常测量 → **立刻**新开一张（无同日抑制、无每日张数上限）。  
5. 没有新上传则不开克隆单。  

列表若 `hitCount > 1`，展示「共 n 项异常」。

## 6. 随访单（回执 / 审阅）

P0 即落表，用 `form_type` 区分，**不是**完整随访排期模块。

关单与随访同一事务：先插 `followup_record`，再 `workspace_task.status=DONE`。

督促/异常：未领取（`assignee_staff_id` 空或不是自己）→ 400「请先领取任务」。  
入组/出方案：关单走条件自闭，不走本接口。

### 6.1 `PLAN_NUDGE` 回执

| 字段 | 必填 | 取值 |
|------|------|------|
| `contactChannel` | 是 | `PHONE` / `WECOM` / `IN_PERSON` / `OTHER` |
| `contactResult` | 是 | `REACHED` / `UNREACHED` |
| `informedCheckin` | `REACHED` 时是 | 是否已告知到 C 端打卡 |
| `patientFeedback` | 否 | 文本 |
| `note` | 否 | 文本 |

`UNREACHED` 允许提交并关单。

### 6.2 `METRIC_REVIEW`（指标异常处理，写入 `followup_record`）

| 字段 | 必填 | 取值 |
|------|------|------|
| `contactTarget` | 是 | `PATIENT` 患者本人 / `PARENT` 父母 / `SPOUSE` 配偶 / `CHILD` 子女 / `FRIEND` 朋友 / `OTHER_RELATIVE` 其他亲友 |
| `followupMethod` | 是 | `PHONE` 电话 / `FACE_TO_FACE` 面对面 / `ONLINE` 在线沟通 / `WECHAT` 微信 / `SMS` 短信 / `CLINIC` 门诊 / `HOME` 家庭 |
| `abnormalReason` | 是 | 异常原因，≤400 字 |
| `guidance` | 否 | 指导建议，≤400 字 |

一条任务可有多次表单历史（退回后再领再填只允许 OPEN 时提交一次成功关单；关单后不可再改，纠错走新任务）。

## 7. 权限与审计

与现有机构工作台一致：必须有 `currentOrgId`，患者须本机构 ACTIVE membership。

| 角色 | 公共池 | 我的待办 | 全部 | 领取/填单 | 分派 | 退回 | 无单取消 |
|------|--------|----------|------|-----------|------|------|----------|
| `CARE_MANAGER` | 本机构四类 | 自己 | 否 | 四类可领；督促/异常须领后填单 | 仅自己名下转交 | 自己名下 | 否 |
| `DOCTOR` | 本机构 **仅**督促/异常 | 自己（含被分派的入组/出方案） | 否 | 公共池仅督促/异常可领 | 仅自己名下转交 | 自己名下 | 否 |
| `TENANT_ADMIN` | 本机构四类 | 自己 | 是 | 四类可领 | 任意 OPEN | 任意 OPEN | 是 `CANCELLED` |

审计 `AuditActionEnum`（新增）：

| action | 时机 |
|--------|------|
| `WORKSPACE_TASK_OPEN` | 系统开单（可抽样，避免日批刷爆；P0 开单不写 audit，只写任务行 `source`） |
| `WORKSPACE_TASK_CLAIM` | 领取 |
| `WORKSPACE_TASK_ASSIGN` | 分派 |
| `WORKSPACE_TASK_RELEASE` | 退回公共池 |
| `WORKSPACE_TASK_DONE` | 关单（含条件自闭、填单、取消） |
| `FOLLOWUP_RECORD_COMPLETE` | 提交督促/异常处理随访并关单 |

`audit_log.target_type`：`workspace_task` / `followup_record`；`details` 含 `taskType`、`peopleId`、`recordType`、退回原因。  
开单高频走任务表 + Job `detail_json` 计数，不写每条 `audit_log`。

## 8. 数据模型

督促回执与指标审阅均写入 **`followup_record`**（`record_type=PLAN_NUDGE|METRIC_REVIEW`）。空壳表 `follow_up_form` / `follow_up_task` / `alert_ticket` 已删除。

标准列：`pk_id` / `id` / `is_deleted` / `gmt_*`（与全库一致）。

### 8.1 `workspace_task`

| 列 | 类型 | 说明 |
|----|------|------|
| `tenant_id` `org_id` `people_id` | VARCHAR(32) | 机构待办，org 必填 |
| `task_type` | VARCHAR(32) | 见 §2 |
| `biz_key` | VARCHAR(64) | 去重业务键 |
| `open_dedup_key` | VARCHAR(128) | 生成列：`OPEN` 时 `{task_type}:{biz_key}`，否则 `{id}` |
| `status` | VARCHAR(16) | `OPEN`（展示**待处理**）/ `DONE`（展示**已完成**）/ `CANCELLED`（已取消）/ `EXPIRED`（已过期） |
| `priority` | VARCHAR(16) | `HIGH` / `MEDIUM` / `LOW` |
| `assignee_staff_id` | VARCHAR(32) | 空=公共池 |
| `title` | VARCHAR(128) | |
| `summary` | VARCHAR(512) | 列表摘要 |
| `payload_json` | JSON | 类型特有快照 |
| `source` | VARCHAR(16) | `EVENT` / `JOB` / `MANUAL`（P0 无手工开这四类） |
| `close_reason` | VARCHAR(16) | `CONDITION` / `FORM` / `EXPIRED` / `CANCEL` |
| `due_at` | DATETIME | 可空；按类型 SLA：入组开单日当天 23:59；方案/督促/异常为开单日起第 3 天 23:59 |
| `opened_at` `done_at` | DATETIME | |
| `done_by_staff_id` | VARCHAR(32) | 条件自闭可空（系统） |

唯一：`uk_workspace_task_id (id)`；`uk_workspace_task_open (tenant_id, org_id, open_dedup_key, gmt_deleted)`。  
索引：`(org_id, status, assignee_staff_id)`、`(org_id, people_id, status)`、`(org_id, task_type, status)`。

优先级 P0 写死：`TEAM_ASSIGN`/`PLAN_CREATE`/`PLAN_NUDGE`/`METRIC_ALERT` 均为 `HIGH`（可后续按 hitCount/streak 调）。

### 8.2 `followup_record`（督促/异常/定期随访）

见 [`随访-产品与技术方案.md`](./随访-产品与技术方案.md)。关单时写入，替换原 `follow_up_form`。

## 12. 验收用例

| # | 用例 | 期望 |
|---|------|------|
| 1 | 建档未入组，执行扫描 | 公共池出现 `TEAM_ASSIGN`（当天即可） |
| 2 | 已有 OPEN 入组单再扫 | **不**重复开 |
| 3 | 当天入组（尚未出任务或已出） | 有 OPEN 则自闭；公共池其余改派主责 |
| 4 | 当天入组、当天无方案，执行扫描 | 主责个人池出现 `PLAN_CREATE` |
| 5 | 已有 OPEN 方案单再扫 | **不**重复开 |
| 6 | 未领取即发布方案 | `PLAN_CREATE` 仍自闭 |
| 7 | 连续 3 天方案未完成 | `PLAN_NUDGE` |
| 8 | 已接通关单后 streak 仍 ≥3 | **不再**开新督促 |
| 9 | 已接通后某天打满，之后又连续 3 天未完成 | 开新 `PLAN_NUDGE` |
| 10 | UNREACHED 关单、次日 streak 仍 ≥3 | 开新督促 |
| 11 | 未领取填督促/审阅 | 400 |
| 12 | 家庭血压一次异常、诊室旧值正常 | 开 1 张 `METRIC_ALERT`，hits 含该条 |
| 13 | 上午、下午各一次异常（未关单） | **仍一张** OPEN，hits 含 2 条 |
| 13b | 同患者血压+血糖+心率异常未关 | **仍一张** OPEN，hits 含多族 |
| 14 | 开单后该条之后录了正常值 | 该单仍 OPEN，hits 仍是当时异常 |
| 15 | 审阅关单后当天又上传新异常 | **立刻**新开一张（新 sourceRecordId） |
| 16 | 关单后没有新上传 | 不开克隆单 |
| 17 | 同一 sourceRecordId 重复上报 | 不重复计入 hits |
| 18 | 仅腰围异常 | 不开单 |
| 19 | 医生看公共池 | 不见入组/出方案 |
| 20 | 两人同时领取 | 一人成功 |
| 21 | 双实例 Job | ShedLock 不双开 |

## 13. 风险

| 风险 | 缓解 |
|------|------|
| 日批对全机构依从性计算偏重 | `batchSize` 分页；先复用看板批量查询 |
| 前端异常口径与 Job 不一致 | 后端 `MetricAbnormalEvaluator` 为 SSOT；前端展示继续用同一套默认值 |
| 开单风暴（指标频繁上报） | 每患者仅一张 OPEN；新异常并入 hits，不刷多张待办 |
| 已接通后看板仍红、工作台无督促 | 本轮只催一次；验收与培训需说明 |
| 与「看板红」感觉不一致 | 看板含用药未完成；P0 **不含**用药催办 |

## 14. 决策冻结摘要

| 主题 | 冻结 |
|------|------|
| Inbox | 单表 `workspace_task`；公共池 vs 个人池 |
| 关督促/异常 | 必须随访单；未接通可关 |
| 入组/出方案 | 可领；做完自闭 |
| 入组开单时钟 | Job 扫描时未入组即开（取消「当天不算」） |
| 督促再开 | 已接通：等连续打断；未接通：可次日再开 |
| 异常恢复 | 不关单；审阅 trigger 快照 |
| 血压 | 时间最近一次，不论诊室/家庭 |
| 医生公共池 | 只见督促/异常 |
| 用药催办 | P0 不做 |
| 默认处理人 | 主责健管师；无则公共池 |
| 方案 SLA | Job 扫描时已入组且无 ACTIVE 方案即开（取消「当天不算」） |
| 到期时限 | 入组 **1** 天内；方案 / 督促 / 异常 **3** 天内（含开单日，到期日 23:59） |
| 异常开单 | 每患者最多一张 OPEN；新异常并入 `hits` |
| 异常再开 | 审阅关单后有新测量立刻再开；同 sourceRecordId 不重复 |
| 扫描 | 平台 Job `WORKSPACE_TASK_SCAN` |
| 预留表 | 已删除空壳 `alert_ticket` / `follow_up_task` / `intervention_record`；随访见 `followup_record` |
