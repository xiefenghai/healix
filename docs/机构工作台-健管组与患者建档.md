| 项 | 内容 |
|---|---|
| 版本 | **v0.2** |

### v0.2 相对 v0.1 的主要变更

| 主题 | 结论 |
|---|---|
| 患者模型 | `patient_*` → **`people_*`**；people = 患者；**租户内隔离** |
| 证件 | 独立表 `people_identity`；支持身份证 / 军官证 / 港澳 / 台胞 / 无证 |
| 同人多证 | **S1**：建档可「挂到已有患者」补证；**S2 合并工具二期** |
| 工作台壳层 | **两段式**：未选机构无业务侧栏；进入机构后出现医护/健管组/患者 |
| 健管组详情 | **下级路由页** `/workspace/care-teams/:id`，不再用右侧抽屉 |
| API | 成员/建档使用 `peopleId`；建档 body 改为证件类型模型 |

## 1. 背景与目标

### 1.1 业务背景

```text
租户 → 机构 → 健管组（网格）→ 成员（医生 / 健管师 / 患者）
                └─ 患者建档（证件或无证）→ 本机构 membership →（可选）入健管组
```

### 1.2 本期目标（In Scope）

| # | 能力 | 说明 |
|---|---|---|
| 1 | **健管组** | 创建/列表/详情页/删除；主责健管师必填、主责医生可选；成员与换主责 |
| 2 | **机构医护** | 本机构健管师/医生；机构侧新开并绑本机构；解绑 |
| 3 | **患者建档** | 多证件类型 / 无证；挂靠已有患者；写 `people_*` + membership + archive |
| 4 | **患者列表** | 本机构 ACTIVE membership；筛健管组 / 未入组；加入健管组 |

### 1.3 非目标（Out of Scope）

- C 端激活登录完整产品化（账号表已租户隔离，注册须带 `tenantId`，激活另文）
- 患者合并工具 S2
- 随访 / 预警 / Care Copilot
- 跨租户建档、同机构患者多组并存

## 2. Grill 决策摘要

### 2.1 初轮 Q1–Q18（仍有效）

| # | 结论 |
|---|---|
| Q1 | 机构侧可**直接新开**医护账号 |
| Q2 | `TENANT_ADMIN` + 本机构 `CARE_MANAGER` / `DOCTOR` |
| Q3 | 主责健管师必填；主责医生可选 |
| Q4 | 同机构患者最多 1 个健管组 |
| Q5 | 建档可无 C 登录；`account_id` 可空 |
| Q6 | 证件**租户内唯一**；hash + cipher + mask |
| Q7 | 机构新开仅 `CARE_MANAGER` / `DOCTOR` |
| Q8 | 删除医护 = **仅解绑**；主责须先换 |
| Q9–Q18 | 见 v0.1 附录；其中「patient」语义现统一为 **people** |

### 2.2 模型重构轮（Q7'–Q15'）

| # | 结论 |
|---|---|
| 主键 | 库表/外键统一 **`people_id`**（API 同步 `peopleId`） |
| 隔离 | **租户内唯一**；租户间完全隔离（同真人跨租户 = 两条 people） |
| 账号 | `people_account` **按租户隔离**（username 租户内唯一） |
| 多证 | 一人多证；同人同类型最多一条 |
| 无证 | 允许；须手填性别 + 出生日期 |
| 同人不同证 | **S1 挂靠已有**（本期）；S2 合并二期 |
| 建档入口 | 一次完成：选证件类型 / 无证 / 可选挂靠 |
| 表名 | `people_*`（无 `sys_` 前缀） |

## 4. 领域模型

### 4.1 ER

```text
tenant 1───* people_profile（患者，租户隔离）
                ├── 0..1 people_account（C 登录，可空）
                ├──* people_identity（证件）
                ├──* people_basic_archive（按建档机构）
                ├──* people_org_membership
                └── 0..1 people_care_assignment（每租户）

organization 1───* care_team
                    ├── primary_care_manager_staff_id（必填）
                    ├── primary_doctor_staff_id（可空）
                    └──* care_team_member
                              ├── STAFF → staff_profile
                              └── PATIENT → people_profile（people_id）
```

### 4.2 表设计

#### `people_profile`

| 列 | 说明 |
|---|---|
| id | `people_id` |
| tenant_id | **必填**，租户隔离 |
| account_id | 可空 → `people_account` |
| display_name / gender / birthday / name_pinyin | |
| allergens_json 等 | 预留 |
| timestamps, deleted | |

#### `people_identity`

| 列 | 说明 |
|---|---|
| tenant_id, people_id | |
| identity_type | `ID_CARD` / `MILITARY_ID` / `HK_MACAU_PASS` / `TAIWAN_PASS` / `OTHER` |
| identity_value_hash / cipher / mask | |
| UK | `(tenant_id, identity_type, hash)`；`(people_id, identity_type)` |

#### `people_basic_archive` / `people_org_membership` / `people_care_assignment`

与原 `patient_basic_archive` 等职责相同，外键为 **`people_id`**。

#### `care_team` / `care_team_member`

同 v0.1；成员患者列名为 **`people_id`**（`member_type=PATIENT`）。

体征 / Agent / `audit_log` 等 PHI 引用列亦为 **`people_id`**。

### 4.3 枚举

| 枚举 | 值 |
|---|---|
| `PeopleIdentityTypeEnum` | 见上 |
| `CareTeamMemberTypeEnum` | `STAFF` / `PATIENT` |
| `PatientArchiveSourceEnum` | `B_SIDE` / `C_JOIN` |
| `GenderEnum` | `MALE` / `FEMALE` / `UNKNOWN` |

## 5. 关键流程

### 5.1–5.5 健管组 / 医护

逻辑同 v0.1（主责自动入组、解绑禁主责、删组留 membership）。care_assignment 表名现为 `people_care_assignment`。

### 5.6 患者建档（落地）

```text
校验 name
若 attachPeopleId：
  → 校验同租户 people 存在
  → 若有证件：证件未被他人占用则可 insert people_identity（同类型不重复）
否则若 noIdentity：
  → 须 gender + birthday → 新建 people_profile
否则（有证件）：
  → 按 (tenant, type, hash) 查 identity：命中则复用 people；未命中则新建 people + identity
  → ID_CARD：校验证件并解析性别生日；其他类型：手填性别生日
→ ensure membership(ACTIVE) / basic_archive(B_SIDE) / care_assignment
→ 审计 PATIENT_ARCHIVE_CREATE（resource=people_profile）
```

工具：`IdCardUtil` + `IdCardCrypto`（哈希含 type 前缀，密文同）。

## 6. API（`/api/b/v1`，隐式当前机构）

### 6.1 健管组

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/care-teams` | 列表 `keyword` |
| GET | `/care-teams/{teamId}` | 详情 |
| POST | `/care-teams` | 创建 |
| PUT | `/care-teams/{teamId}` | 改名 |
| DELETE | `/care-teams/{teamId}` | 软删 |
| PUT | `/care-teams/{teamId}/primary` | 换主责 |
| GET/POST/DELETE | `/care-teams/{teamId}/members[...]` | 成员；POST body 用 `peopleId`（患者） |

### 6.2 机构医护

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/org-staff` | `roleCode` / `keyword` |
| POST | `/org-staff` | 新开医护 |
| DELETE | `/org-staff/{staffId}` | 解绑 |

### 6.3 患者

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/org-patients` | `keyword` / `careTeamId` / `unassigned`；响应 `peopleId` + `identityMask` |
| POST | `/patients/archives` | 见下 |

**建档 body：**

```json
{
  "name": "张三",
  "attachPeopleId": null,
  "noIdentity": false,
  "identityType": "ID_CARD",
  "identityValue": "…",
  "gender": null,
  "birthday": null
}
```

列表证件字段：`identityMask` / `identityType`（优先身份证）。

## 7. 前端（机构工作台）

### 7.1 两段式壳层

| 阶段 | 侧栏 | 说明 |
|---|---|---|
| 未选机构 / 在 `/workspace/orgs` | **隐藏** | 仅选机构 |
| 已进入机构且非选机构页 | 机构医护 / 健管组 / 患者管理 | 顶栏机构 Tag →「切换机构」回选机构页 |

路由守卫：业务页 `meta.requireOrg`，无 org 回 `/workspace/orgs`。

### 7.2 菜单与路由

| 路径 | 说明 |
|---|---|
| `/workspace/orgs` | 选择机构 |
| `/workspace/staff` | 机构医护 |
| `/workspace/care-teams` | 健管组列表 |
| `/workspace/care-teams/:teamId` | **健管组详情下级页**（非抽屉） |
| `/workspace/patients` | 患者管理 |

### 7.3 页面要点

- **机构医护**：列表 + 新开 + 解绑  
- **健管组列表** → 点详情进下级页：改名 / 主责 / 成员 / 删组  
- **患者管理**：建档（证件类型、无证、挂靠已有、性别出生年月展示）+ 筛组 + 加入健管组  

业务提示文案：**中文**（后端 `BusinessException` 已中文化）。
