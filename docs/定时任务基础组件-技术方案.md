## 1. 背景与目标

### 1.1 背景

Healix 为 Spring Boot Modulith 单体（MySQL + Redis）。需要统一批处理能力，例如：

- 用药过结束日仍为 `ACTIVE` 时，仅靠列表惰性过期无法覆盖依从性看板、Agent 上下文等路径
- 后续依从性日结、方案窗口扫描、提醒推送等也会复用同一套调度

当前工程无 `@Scheduled` 基础设施；不宜每个业务各自硬编码且无法在 Ops 启停、改 Cron、查日志。

### 1.2 配置面决策

定时任务是 **平台基础设施**，不是租户内组织治理。

| 决策 | 口径 |
|---|---|
| 谁配置 | Ops（`SUPER_ADMIN` 写 / `OPERATOR` 读） |
| 配置粒度 | **全平台一份**（按 `jobCode`） |
| UI | Ops 侧栏 **平台任务**（与租户列表平级） |
| 不做什么 | 租户详情 Tab、B 端租户管理员、按租户改 Cron |

### 1.3 一句话目标

提供可复用的 **平台级**定时任务组件：Handler 代码注册、配置落库、Ops 全局页启停/改 Cron/整轮手动跑/看日志；首个任务批量过期用药。

### 1.4 本期目标（In Scope）

| # | 能力 | 说明 |
|---|---|---|
| 1 | 任务目录 + 平台配置 | 内置 `jobCode`；库表存启停、Cron、调度游标 |
| 2 | 进程内调度 + 分布式锁 | ShedLock；`healix:job:lock:{jobCode}` |
| 3 | 执行日志 | 每次调度/手动触发一条平台 run |
| 4 | 手动触发 | 整轮执行（所有启用租户范围内的业务逻辑） |
| 5 | `MEDICATION_EXPIRE` | 跨启用租户 bulk 将到期 `ACTIVE` → `STOPPED` |
| 6 | Ops 全局页 | 列表 / 启停 / Cron / 手动跑 / 日志 |

### 1.5 非目标（Out of Scope）

| 项 | 说明 |
|---|---|
| 独立调度中控台 | 不上 XXL-JOB / PowerJob Admin |
| 动态脚本 / 动态类名 | 仅白名单 Handler |
| 租户级配置 | 无 per-tenant def / override / enabled |
| 单租户手动跑 | P0 不做 |
| B 端暴露 | 本期否 |
| 替换惰性过期 | 与定时 **并存** |
| params 在线编辑 | P0 写死 Catalog/代码默认（如 `batchSize`） |

## 2. 技术选型

### 2.1 候选对比

| 方案 | 结论 | 理由 |
|---|---|---|
| **Spring Scheduling + ShedLock（Redis）** | **采用** | 已有 Redis；Modulith 契合；自建 Ops UI |
| Quartz JDBC | 不选（一期） | 偏重 |
| XXL-JOB / PowerJob | 不选 | 独立 Admin 与自建全局页重复 |
| JobRunr | 远期备选 | 一期收益不明显 |

### 2.2 锁定技术栈

| 层 | 选型 |
|---|---|
| 触发时钟 | `@EnableScheduling`，tick ≈ 60s 扫到期平台任务 |
| 分布式锁 | ShedLock + Redis（`healix:job:lock:{jobCode}`） |
| 配置 / 日志 | MySQL：`sys_job_def`、`sys_job_run`（**无租户配置维**） |
| Handler | Spring Bean + `JobHandler` SPI |
| Cron | Spring 6 位；时区 `Asia/Shanghai` |
| 前端 | Ops 门户新增「平台任务」路由与页面 |

### 2.3 选型原则

1. 配置在产品内（Ops 全局页）  
2. 执行在进程内  
3. Handler 白名单  
4. 业务数据仍按启用租户范围过滤（Handler 内约束，非每租户一条任务）  
5. 写操作限 `SUPER_ADMIN`

## 3. 总体架构

```text
┌─────────────────────────────────┐
│  Ops · 平台任务（全局页）         │  SUPER_ADMIN / OPERATOR
└──────────────┬──────────────────┘
               │ /api/ops/v1/jobs
               ▼
┌─────────────────────────────────┐
│  OpsJobController               │
│  JobAdminService                │
└──────────────┬──────────────────┘
               │
     ┌─────────┴─────────┐
     ▼                   ▼
 sys_job_def         sys_job_run
 （按 job_code）      （平台级一条/次）
     ▲
     │ tick ~60s
┌────┴────────────────────────────┐
│  JobSchedulerService            │
│  → ShedLock(jobCode)            │
│  → JobHandlerRegistry           │
│  → Handler.execute(平台 ctx)    │
│  → 写 run + 更新 next_fire      │
└─────────────────────────────────┘
```

### 3.1 执行模型

1. **JobCatalog（代码）**：`jobCode`、默认 Cron、说明、默认 params（不开放 UI）  
2. **种子化**：应用启动或首次打开平台任务页时，按目录 upsert `sys_job_def`（每 `job_code` 一行）  
3. **Tick**：`enabled=1 AND next_fire_at <= now` → 抢锁 → 执行 → 写 run → 推进 `next_fire_at`  
4. **Ops 可改**：启停、Cron；不可改 `jobCode` / Handler 绑定；params P0 不改  

### 3.2 与用药过期的关系

| 路径 | 作用 |
|---|---|
| 列表/详情惰性过期 | 打开页立刻正确 |
| `MEDICATION_EXPIRE` 定时 | 批处理刷 `status`，供看板/Agent 等路径 |

两者 **并存**。

## 5. 核心抽象

### 5.1 JobHandler

```java
public interface JobHandler {
    String jobCode();

    /** 平台级执行；禁止依赖 HTTP RequestContext */
    JobResult execute(JobContext ctx) throws Exception;
}
```

### 5.2 JobContext / JobResult

| JobContext | 说明 |
|---|---|
| `jobCode` | |
| `runId` | |
| `params` | Catalog/库内默认（P0 无 UI 编辑） |
| `triggerType` | `SCHEDULE` / `MANUAL` |
| `clock` | 默认 `Asia/Shanghai` |

**无 `tenantId`**：平台任务自行决定如何枚举启用租户或写跨租户 SQL。

| JobResult | 说明 |
|---|---|
| `message` | 摘要 |
| `detail` | 写入 `detail_json`（如 `updatedRows`、`tenantCount`） |

### 5.3 Handler 约束

1. 幂等  
2. 大批量分页 / 限流（`batchSize` 来自默认 params）  
3. 业务范围默认限定 **`TenantStatusEnum.ACTIVE` 租户**  
4. 单次超时建议 5–10 分钟；超时 → 整次 `FAILED`  
5. **不**把「某个租户业务失败」上升为必须中止整轮的产品语义；能 bulk 则 bulk  

### 5.4 一期内置 Handler

| jobCode | 默认 Cron | 策略 | 说明 |
|---|---|---|---|
| `MEDICATION_EXPIRE` | `0 5 0 * * ?` | **Bulk（Q12-A）** | 对启用租户：`ACTIVE` 且结束日已过 → `STOPPED`；结束日语义对齐 `MedicationService.isPastEndDate`（闭区间，次日过期） |

默认 params（代码，非 UI）：

```json
{ "batchSize": 500 }
```

实现要点：分页 `UPDATE`/`SELECT id` 循环；限定 `tenant.status = ACTIVE`（或 `tenant_id IN (...)`）；`detail_json` 记影响行数即可。

## 7. 调度与并发

### 7.1 Tick

```text
每 ~60s
  → 查 enabled=1 AND next_fire_at <= now()
  → 对每个平台 job:
       tryLock(jobCode, lockAtMost=10m)
       失败 → 跳过
       成功 →
         insert run(RUNNING)
         handler.execute(ctx)
         正常返回 → SUCCESS + detail
         未捕获异常/超时 → FAILED
         更新 def.last_* + next_fire_at
         unlock
```

### 7.2 Misfire

延迟过大时跳到 **下一个未来触发点**，不连环补跑。业务补数由 Handler 幂等全量/增量扫描完成（用药过期扫全部到期行）。

### 7.3 手动触发

- 同一把平台锁；执行中再次触发 →「任务执行中」  
- `trigger_type=MANUAL`；**不**重置 `next_fire_at`  
- 二次确认文案强调 **全平台整轮**  

### 7.4 多实例

ShedLock 保证同 `jobCode` 同时仅一节点执行。

### 7.5 失败定义（Q15）

| 结果 | 条件 |
|---|---|
| `SUCCESS` | Handler 正常返回（含更新 0 行） |
| `FAILED` | 未捕获异常、超时、锁内基础设施失败 |
| 不采用 | 「某租户业务失败 → 整轮失败」作为产品语义 |

## 8. API 设计

前缀：`/api/ops/v1/jobs`  
鉴权：Ops 登录。

| 角色 | 权限 |
|---|---|
| `SUPER_ADMIN` | 列表 / 改启停与 Cron / 手动跑 / 日志 |
| `OPERATOR` | 列表 / 日志只读 |

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/` | 平台任务列表（无则种子化） |
| `PUT` | `/{jobCode}` | `{ enabled, cronExpr }` |
| `POST` | `/{jobCode}/run` | 整轮手动触发 |
| `GET` | `/{jobCode}/runs` | 日志分页 |

### 8.1 更新示例

```json
{
  "enabled": true,
  "cronExpr": "0 5 0 * * ?"
}
```

### 8.2 校验

| 项 | 规则 |
|---|---|
| `jobCode` | 必须在 JobCatalog |
| `cronExpr` | 可解析；最短间隔 ≥ 1 分钟（可配） |
| 权限 | `OPERATOR` 写操作 → 403 |

## 10. 安全与隔离

| 风险 | 对策 |
|---|---|
| 扫到停用租户 | Handler 仅 `tenant.status = ACTIVE`（或等价 SQL 条件） |
| 动态代码 | 白名单 `jobCode` |
| Cron 过频 | 服务端最短间隔 |
| 长任务 | batchSize + 超时 + `lockAtMost` |
| 日志泄密 | `detail_json` 只记计数类指标 |
| 误触全平台手动跑 | UI 二次确认 + 仅 SUPER_ADMIN |

## 12. 验收标准（P0）

1. Ops 全局「平台任务」可见 `MEDICATION_EXPIRE`，可启停与改 Cron  
2. `OPERATOR` 只读；无法改配/手动跑  
3. 到点执行；`sys_job_run` 有 `SUCCESS`；`next_fire_at` 推进  
4. 双实例下同 `jobCode` 不双跑  
5. 手动整轮可跑；执行中再次触发被拒  
6. `ACTIVE` 租户下「结束日已过仍 ACTIVE」的用药，跑完后为 `STOPPED`；`SUSPENDED`/`CLOSED` 租户不被扫（或符合既定过滤）  
7. 无 `/tenants/{id}/jobs`；B 端无法访问  
8. 列表惰性过期行为仍在
