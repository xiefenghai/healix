## 1. 背景与要解决的问题

现状（2026-10 盘点）共 4 个引擎：CDRS、高血压风险、肥胖筛查、糖尿病血糖控制分标。主要问题：

| # | 问题 | 本次处理 |
|---|---|---|
| P1 | 只有健管师手动点「评估」才生成结果；数据变了结果不变；确诊后旧的风险结果仍出现在标签里 | §7 自动重算 + 适用性失效 |
| P2 | 患者列表每行调用完整 `overview()`，每人十几次查询（N+1） | §8 最新结果表 + 批量读 |
| P3 | 语义混乱：高血压风险的 level 是血压分级、score 存收缩压；肥胖 score 存 BMI；等级名/引擎名/颜色在三处 switch 硬编码 | §4 统一结果模型 |
| P4 | 阈值与评分表 Java 和前端 4 个 `*-rules.ts` 各写一份 | §9 规则由后端下发 |
| P5 | `extras` 无结构，前端按引擎写死解析 | §4.3 结构化结果 |
| P6 | 60+ 字段的大上下文，新增引擎要改三处；输入快照全量存储 | §5 输入字段注册表 |
| P7 | 文档过时 | 本文替代 |
| P8 | 高危无闭环，管理方案、报告、Agent 不读评估结果 | §10 闭环 |
| P9 | 规则需要的数据很多系统里没有来源（妊娠糖尿病史、类固醇用药、靶器官损害等） | §6 评估问卷 |

另清理：China-PAR 残留代码（`recordChinaPar`、`buildChinaParPrep`、`ChinaParRecordRequest`、`ChinaParPrepDto`）；历史 China-PAR 快照保留可查。

## 2. 两大类评估

以病种为轴，每个病种一对引擎，按「是否已确诊」二选一：

| 病种 | 患病风险评估（未确诊） | 疾病严重等级分层（已确诊） |
|---|---|---|
| 糖尿病 | `CDRS` 中国糖尿病风险评分 | `DIABETES_SEVERITY` 血糖控制分层（原「血糖控制分标」，规则不变） |
| 高血压 | `HYPERTENSION_RISK` 高血压患病风险 | `HYPERTENSION_SEVERITY` 心血管风险分层（**新增**） |
| 肥胖 | `OBESITY_RISK` 肥胖筛查（原 `OBESITY_SCREEN`） | `OBESITY_SEVERITY` 肥胖症分层（**新增**） |

- **确诊判定**：病种档案或基础档案「现有疾病」勾选（沿用现有 `hasKnownX`）。
- **类别字段** `category`：`RISK` | `SEVERITY`。库内 `kind` 列改存这两个值；存量 `INCIDENT_RISK` → `RISK`，`CONTROL_STATUS` → `SEVERITY`。
- **引擎编码**：`DIABETES_CONTROL_LABEL` → `DIABETES_SEVERITY`，`OBESITY_SCREEN` → `OBESITY_RISK`，存量快照一次性迁移。
- **互斥**：同一病种同一时刻只有一个引擎「生效」。确诊后风险引擎的最新结果置为失效（不再出现在标签），历史仍可查。
- **风险引擎发现疑似已患病**（例如未确诊但血压达 1 级、BMI ≥28）：结果给出「疑似，建议确诊并建病种档案」，不自动建档。

## 3. 规则

### 3.1 患病风险评估

**CDRS**：规则不变（评分 ≥25 或命中任一高危因素 → 高风险）。问卷补齐原来「未采集」的高危因素：妊娠期糖尿病史、类固醇糖尿病史、多囊卵巢综合征 / 黑棘皮症、动脉粥样硬化性心血管病、长期服用抗精神病药 / 抗抑郁药 / 他汀。正在降压 / 调脂治疗从用药记录推断（药品目录分类 `BP` / `LIPID`）。

**高血压患病风险**：输出改为风险等级，血压分级降为一个维度：

| 统一等级 | 条件 |
|---|---|
| 高 | 血压达 1 级及以上（疑似高血压，建议确诊），或心脑血管病风险高危组合 |
| 中 | 高血压前期，或命中任一易患因素 |
| 低 | 血压正常且未命中易患因素 |

血压取值从「最新一次」改为**近 4 周均值**（至少 2 次读数；不足时取最新一次并标注）。问卷补齐：长期精神紧张、被动吸烟、高盐饮食、早发停经。

**肥胖筛查**：等级改为统一等级——正常 → 低；超重或中心性肥胖 → 中；BMI ≥28 → 高（疑似肥胖症，建议确诊）。问卷补齐：腰围自测、体脂率（可选）。

### 3.2 疾病严重等级分层

**糖尿病（血糖控制分层）**：规则不变（红 / 黄 / 绿 / 准绿 / 无标）。映射统一等级：红 → 很高，黄 → 中，绿与准绿 → 低，无标 → 无数据。

**高血压（心血管风险分层，新增）**，依据《中国高血压防治指南（2018 年修订版）》：

| 其他危险因素与病史 | 正常高值 130–139/85–89 | 1 级 | 2 级 | 3 级 |
|---|---|---|---|---|
| 无 | — | 低危 | 中危 | 高危 |
| 1–2 个危险因素 | 低危 | 中危 | 中/高危 | 很高危 |
| ≥3 个危险因素，或靶器官损害，或慢性肾病 3 期，或无并发症的糖尿病 | 中/高危 | 高危 | 高危 | 很高危 |
| 临床并发症，或慢性肾病 ≥4 期，或有并发症的糖尿病 | 高/很高危 | 很高危 | 很高危 | 很高危 |

- 「中/高危」「高/很高危」两格**暂取较高档**（D1：暂定口径，待医学团队校准；规则说明与结果卡需标注）。
- **血压分级取值**：病种档案「既往最高收缩压/舒张压」优先（指南按未治疗时血压分层）；没有则用近 4 周均值。
- **危险因素**（指南口径，阈值与健康管理规范不同）：男 >55 / 女 >65 岁；吸烟或被动吸烟；糖耐量受损或空腹血糖异常；血脂异常（总胆固醇 ≥5.2 或低密度脂蛋白 ≥3.4 或高密度脂蛋白 <1.0 mmol/L）；早发心血管病家族史；腹型肥胖或 BMI ≥28；同型半胱氨酸 ≥15 μmol/L。
- **靶器官损害**：检验 eGFR 30–59 或血肌酐轻度升高、UACR 30–300 自动判定；左心室肥厚、颈动脉内中膜增厚或斑块、脉搏波速度、踝臂指数来自问卷（专业项，仅 B 端可填）。
- **临床并发症**：「现有疾病」里的冠心病、脑卒中、心衰、慢性肾病自动判定；eGFR <30、UACR >300 自动判定；外周血管病、视网膜病变、房颤来自问卷。
- **糖尿病**：病种档案判定；「有并发症」来自问卷（糖尿病肾病 / 视网膜病变 / 神经病变）。
- 统一等级：低危 → 低，中危 → 中，高危 → 高，很高危 → 很高。
- 计算结果同时与病种档案手填的「心血管风险分层」对比，不一致时提示，不自动覆盖。

**肥胖症分层（新增）**，依据《肥胖症诊疗指南（2024 年版）》BMI 分度 + 并发症分期（参考 Edmonton 肥胖分期）：

| 维度 | 分档 |
|---|---|
| BMI 分度 | 轻度 28.0–32.4；中度 32.5–37.4；重度 37.5–49.9；极重度 ≥50 |
| 并发症分期 | 0 期：无相关异常；1 期：亚临床异常（高血压前期、空腹血糖受损、转氨酶升高等）；2 期：已患相关慢病（高血压、2 型糖尿病、睡眠呼吸暂停、骨关节炎、脂肪肝、多囊卵巢等）；3 期：终末器官损害（心梗、心衰、卒中、糖尿病并发症等） |

统一等级取两者较高者：轻度且 0–1 期 → 低；中度或 2 期 → 中；重度或 3 期 → 高；极重度 → 很高。睡眠呼吸暂停、骨关节炎、脂肪肝等来自「现有疾病」或问卷。**暂定口径，待医学团队校准**（D15）。

## 4. 统一结果模型

### 4.1 引擎接口

```java
public interface AssessmentEngine {
    String code();
    AssessmentCategory category();          // RISK | SEVERITY
    String diseaseCode();                   // diabetes | hypertension | obesity
    GuidelineRef guideline();
    String rulePackVersion();
    String label();                         // 引擎显示名
    List<LevelDef> levels();                // 本引擎原生等级：code、名称、统一等级
    Set<InputField> inputs();               // 本引擎用到的输入字段
    Set<InputField> requiredInputs();       // 缺任一则 INCOMPLETE
    boolean applicable(AssessmentInputs in);
    AssessmentResult evaluate(AssessmentInputs in);
    RuleSheet ruleSheet();                  // 规则说明，供前端展示
}
```

等级名称、引擎名称、颜色全部由 `levels()` / `label()` 提供，删除编排器和标签组件里的 switch。

### 4.2 字段语义

| 字段 | 含义 |
|---|---|
| `level` | 引擎原生等级（如 `GRADE_2`、`RED`、`MODERATE_OBESITY`） |
| `tier` | 统一等级 `LOW` / `MID` / `HIGH` / `VERY_HIGH`，用于着色、排序、闭环；无数据为空 |
| `score` | **只存真正的分数**（目前只有 CDRS），其余为空 |
| `status` | `COMPLETE` / `INCOMPLETE` |

### 4.3 结构化结果（替代自由 `extras`）

```json
{
  "advice": "…",
  "dimensions": [{ "code": "BP_GRADE", "label": "血压分级", "value": "2级", "tier": "HIGH" }],
  "items":      [{ "code": "AGE", "label": "年龄", "value": "52 岁", "points": 13, "rationale": "50–54 岁 → 13 分" }],
  "factorGroups": [{
    "code": "MAJOR_RF", "title": "心血管危险因素",
    "hits":      [{ "code": "SMOKING", "label": "吸烟", "detail": "当前吸烟", "source": "ARCHIVE" }],
    "unchecked": [{ "field": "LVH", "label": "左心室肥厚", "questionnaire": true }]
  }],
  "missing": [{ "field": "WAIST", "label": "腰围", "fillVia": ["METRIC", "QUESTIONNAIRE"] }],
  "comparisons": [{ "label": "档案手填分层", "value": "中危", "consistent": false }]
}
```

前端只按这个结构通用渲染，不再按引擎写死。

## 5. 输入字段注册表

用 `InputField` 枚举替代 60+ 字段的大上下文。每个字段声明：

| 属性 | 说明 |
|---|---|
| `code` / `label` | 如 `GDM_HISTORY` / 妊娠期糖尿病史 |
| `type` | `NUMBER` / `BOOL` / `ENUM` / `MULTI` |
| `sources` | 取值来源与优先级，如 `[DISEASE_ARCHIVE, QUESTIONNAIRE]` |
| `question` | 问卷题面、选项、单位、范围 |
| `audience` | `PATIENT`（患者可答）/ `STAFF`（专业项，仅 B 端） |
| `writeBack` | 问卷答案写回哪里：档案字段 / 指标 / 仅评估事实表 |

**取值三态**：有值 / 明确为否 / 未知。必填字段未知 → `INCOMPLETE`；非必填未知 → 进 `unchecked`，不编造命中。

**加载方式**：`AssessmentInputLoader` 按引擎声明的字段一次批量取数：

- 指标最新值调用一次（现在调用 7 次）
- 基础档案读一次（现在读 3 次）
- 病种档案读一次（现在读 2 次）
- 检验、近 14 天血糖、近 4 周血压、在用药品各一次

**输入快照**只保存该引擎声明的字段，每个值带来源和记录时间。

## 6. 评估问卷

### 6.1 定位

问卷是**补数据的手段**，不是独立的量表。题目不手工配置，而是由「适用引擎声明的输入字段」减去「系统里已有值的字段」动态生成；已有值的题目预填，可修改。

### 6.2 入口

| 端 | 入口 | 题目范围 |
|---|---|---|
| B 端（管理后台 / 健管师端） | 疾病评估页「填写评估问卷」；结果卡缺项旁「去问卷补齐」 | 全部字段（含专业项） |
| B 端 | 「发送问卷给患者」→ 患者收到推送 / 待办 | 患者可答字段 |
| C 端 | 「健康评估」页「开始评估」 | 患者可答字段 |

提交后立即重算适用引擎，展示结果。

### 6.3 数据去向（避免两份事实打架）

| 字段类型 | 去向 | 例 |
|---|---|---|
| 档案已有字段 | 写回基础档案 / 病种档案，记修订记录，来源标「问卷」 | 吸烟、运动、家族史、既往最高血压 |
| 测量值 | 写入指标记录，来源标「问卷自报」 | 身高、体重、腰围、血压 |
| 档案没有的字段 | 写入评估事实表 `people_assessment_fact` | 妊娠糖尿病史、类固醇用药、左心室肥厚 |

每次提交另存一条 `assessment_questionnaire_submission`（全部答案、提交人、端、时间），用于审计和回看。

### 6.4 表

```sql
people_assessment_fact (
  id, tenant_id, people_id,
  field_code,          -- InputField.code
  value_json,          -- {"value": true} / {"value": 3.2, "unit": "mmol/L"} / {"value": "UNKNOWN"}
  source,              -- QUESTIONNAIRE_STAFF | QUESTIONNAIRE_PATIENT
  submission_id, recorded_at, recorded_by,
  UNIQUE (tenant_id, people_id, field_code)   -- 只存最新值；历史在 submission
)

assessment_questionnaire_submission (
  id, tenant_id, people_id,
  portal,              -- B | C
  submitted_by,        -- staffId / accountId
  request_id,          -- B 端发起的问卷请求，可空
  answers_json, engines_json, submitted_at
)

assessment_questionnaire_request (    -- B 端发送给患者
  id, tenant_id, people_id, org_id, staff_id,
  fields_json, status,  -- PENDING | SUBMITTED | EXPIRED
  created_at, expires_at, submission_id
)
```

## 7. 自动重算（解决 P1）

1. **输入变更事件**：以下保存成功后发布 `AssessmentInputChangedEvent(tenantId, peopleId)`：
   - 指标、检验、基础档案、病种档案、用药、问卷
2. **脏标记**：事务提交后的监听器写入 `people_assessment_state.dirty_at`。不在请求线程里计算。
3. **重算任务** `ASSESSMENT_RECOMPUTE`：每 2 分钟扫描脏标记，逐人重算全部适用引擎。
4. **每日全量**（凌晨）：处理年龄变化、90 天窗口过期等不随事件变化的情况。
5. **只在结果变化时新增快照**：用 `status + level + tier + 命中项` 计算指纹，不变则只更新「最近计算时间」，避免历史被刷屏。
6. **适用性失效**：确诊后风险引擎在最新表置为失效，标签立即不再显示。
7. 手动「重新评估」保留，`trigger_source` 增加 `AUTO`、`QUESTIONNAIRE`。

## 8. 最新结果表（解决 P2）

```sql
people_assessment_latest (
  tenant_id, people_id, engine_code,          -- 唯一键
  category, disease_code,
  snapshot_id, status, level, level_label, tier, score,
  active,                                      -- 当前是否适用
  assessed_at, evaluated_at,
  UNIQUE (tenant_id, people_id, engine_code)
)
```

- 每次写快照时同步更新。
- 患者列表、驾驶舱、Agent 按 `people_id IN (…)` 批量读，每页一次查询。
- 标签组件只读这张表，不再构建上下文。
- 上线时从存量快照回填，并全量重算一次。

## 9. 规则单一来源（解决 P4）

- 每个引擎提供 `ruleSheet()`：评分表、阈值表、判定说明、指南出处。
- 新接口 `GET /api/b/v1/assessment-rules?engineCode=`，前端通用渲染。
- 删除前端 `cdrs-rules.ts`、`hypertension-rules.ts`、`obesity-rules.ts`、`diabetes-control-label-rules.ts`。

## 10. 闭环（解决 P8）

| 触发 | 动作 |
|---|---|
| 统一等级升到「高 / 很高」（与上一次比较） | 生成工作台任务 `ASSESSMENT_ESCALATION`，同一人同一引擎同一等级不重复生成 |
| 风险引擎提示疑似已患病 | 工作台任务「建议确诊并建档」 |
| 生成管理方案 | 管理方案上下文带入最新评估（等级、命中因素）；面向患者的文字不出现等级用语（D17） |
| 管理报告 | 患者可见报告不含评估；健管师审核时侧栏展示最新评估（D16） |
| Agent | 工具读最新结果表，返回等级与主要命中因素，不再只有标签文字 |

## 12. 定稿口径

| # | 结论 |
|---|---|
| D1 | 高血压分层表「中/高危」「高/很高危」两格**暂取较高档**。规则包标记 `HTN-SEV-2018.1-PROVISIONAL`，规则说明与结果卡显示「暂定口径，待医学团队校准」；医学团队到位后重新校准并升版 |
| D2 | C 端**暂不展示**评估结果（含严重等级分层），避免患者焦虑 |
| D3 | 患者自填问卷**直接生效**并触发重算 |
| D4 | 问卷答案与档案现有值冲突时，提交前列出冲突项**二次确认**；确认后以问卷为准写回，并记修订记录 |
| D5 | C 端「健康评估」结果页**整页下线**（路由与入口移除）；C 端只保留问卷，提交后提示「已提交，你的健康管理师会查看」 |
| D6 | C 端问卷入口：健管师「发送问卷」后的推送 + 首页待办卡；另在「我的 → 健康档案」常驻「完善健康信息」 |
| D7 | 患者确认覆盖档案冲突项后，给负责健管师生成工作台提醒「患者自报信息与档案不一致，已更新」（含新旧值） |
| D8 | 问卷默认只显示缺失题，「查看全部」可展开修改已有值；B 端同样默认只看缺项 |
| D9 | 「不知道」记为未知：必填未知 → 仍 `INCOMPLETE`；非必填未知 → 进「未核实」；不当作「否」 |
| D10 | 自动重算：脏标记 + 每 2 分钟扫描；每日凌晨全量一次 |
| D11 | 审计只记手动评估与问卷提交；自动重算只在快照 `trigger_source=AUTO` 体现 |
| D12 | 高危闭环任务只在统一等级**升级**到高 / 很高时生成一次 |
| D13 | 引擎编码与类别改名并一次性迁移存量（§2） |
| D14 | 风险引擎「疑似已患病」→ 提示 + 工作台任务；结果卡提供「一键建病种档案」（健管师确认后建档，建档后自动切换到分层评估） |
| D15 | 肥胖症分层 = BMI 分度与并发症分期取较高者；规则包 `OBESITY-SEV-2024.1-PROVISIONAL`，同 D1 标注暂定口径 |
| D16 | 管理报告（患者可见）**不含**疾病评估小节；健管师审核报告时侧栏展示最新评估作参考 |
| D17 | 管理方案生成带入评估结果；提示词要求面向患者的文字不得出现「高危 / 很高危 / 分层」等等级用语；B 端 Agent 可直接说明等级 |
| D18 | 问卷可填身高、体重、腰围（写入指标，来源「问卷自报」）；血压不在问卷填，引导去血压记录 |
| D19 | 发给患者的问卷 7 天有效；48 小时未填推送提醒一次；过期后健管师工作台提示「问卷未完成」 |
| D20 | 患者提交问卷不单独通知健管师；依赖 D7（冲突覆盖提醒）与 D12（升级任务）；评估页显示「患者于 X 时填写」 |
| D21 | 健管师移动端与管理后台功能一致（分组结果、填写问卷、发送问卷、规则说明），移动版布局 |

## 13. 合规（沿用 v0.3）

- 定位为健康管理辅助信息，不构成诊断或治疗建议；页面固定免责并展示指南名与规则版本。
- 分层文案用「管理分层 / 风险分层」，不用「确诊分期」。
- 手动评估写审计 `PATIENT_ASSESSMENT_RUN`，问卷提交写 `PATIENT_ASSESSMENT_QUESTIONNAIRE`（含端）；自动重算只体现在快照 `trigger_source`（D11）。
- 输入快照只保存引擎声明的字段。
