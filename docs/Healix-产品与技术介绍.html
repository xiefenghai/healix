05 · AI 主卖点

方案生成 + 单据 OCR

管理方案

  • 运动 / 饮食 / 执行计划结构
  • SSE 边想边出
  • 进草稿箱，发布才生效
  • 同一患者至多 1 个 ACTIVE

单据 OCR

  • 检验 / 检查 / 用药单识图
  • 对话内预填核对
  • 字典对不齐进忽略列表
  • 确认入库才写业务表

演示口播：故意改一处再确认 —— 责任在人。

06 · 运营底座

任务 · 随访 · 档案 · 沟通

工作台任务

  • 类型：随访 / 指标异常 / 打卡跟进 / 方案·报告审阅…
  • 领取 · 分派 · 退回 · 取消
  • 填单：保存草稿 / 提交办结
  • 驾驶舱与工作台同一弹窗

随访与双入口

  • OPEN / DONE / CANCELLED
  • 排期生成 FOLLOW_UP 待办
  • 详情「当场办结」关同类型任务
  • 避免访过了待办还在
07 · 演示怎么讲

六幕业务闭环

1 看三栏→ 2 点人建议→ 3 完成待办→ 4 生成方案→ 5 OCR 入库→ 6 随访闭环

强调落库点

  • 动作卡 / 填单才写库
  • 保存 ≠ 提交
  • 草稿 ≠ 发布

收口

  • 驾驶舱是主入口
  • 方案 + OCR 是卖点
  • 全程人审
08 · 技术架构

 ├── C  aud=c     frontend-user

10 · 落库闸门

为什么模型不直接 UPDATE

能力AI 产出生效
方案draft员工 publish
OCR预填卡确认入库 + 字典
随访填单可保存草稿提交 → DONE + 关任务
可追责 可改草稿 字段进字典 失败可重试
